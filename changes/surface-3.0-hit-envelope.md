**Surface 3.0 / CLI 3.0 — one name for every value: engine attributes are bare and win on collision, `$` belongs to OQX, user data that collides is reached through a handle, and every tool result spells a row the way the language does.** The rule (`spec/surface` §1.2, normative): `$it $key $depth $stop $leaf $frontier $ordinal` are values the LANGUAGE injects into a scope and omgbase adds **no `$` names** — a `$id` or `$path` in a query is now an unknown OQX identifier (absent). Every engine attribute is a bare snake_case name that **wins on collision**, the convention the relations (`children`, `blocks`, `out`, `in`, `doc`, `frontmatter`) always followed: docs `id path raw hash updated_at title tags format`, blocks `id path raw hash updated_at doc_id type text attrs depth ordinal`, nodes `id path doc_id block_id kind name value attrs`, edges `id path doc_id block_id via_id dst_id dst_path uri field dst_kind predicate provenance anchor`, the root row `^id` (the repository). User data is bare too; where an authored key collides with an engine name it is reached through a **source handle** — `data` (NEW: the merged authored view, frontmatter + inline by the property rule, exactly the read a bare non-colliding key performs), `frontmatter`, `inline` — so `data.path` is the author's `path:` key, `data.tags` the authored list, `data.title` the authored title, and `entries(data)` lists every authored top-level key (frontmatter ∪ inline, key order). The loud-error set is **gone**: a bare `id`/`path`/`updated_at`/`hash`/`raw` is simply the attribute (2.x refused it with "did you mean `$path`?"). `title` is the computed title (the first H1, `spec/properties` §3.3); **`tags` is the union of the authored tags and the body `#hashtags`** (deduped, authored first, then hashtags in document order; null when both are absent) — the stored computed `$tags` row is unchanged, the surface changes the attribute, so `spec/properties` did not move. Handle reads **push down**: `data.<k>` is the bare property's SQL, `frontmatter.<k>`/`inline.<k>` the same single-scalar-row subquery scoped by `p.source` (before, every handle member fell back to in-memory evaluation while the bare key was pushed); `entries(<handle>)` and a whole-handle reference stay residual. Contextual words (`limit order offset follow collect count first distinct desc by in`) parse as fields in expression position; `select from where is not and or true false null` never do.

**Results — same value, same name, everywhere.** A query hit is `{ id, path, …projection }` (the 2.x spelling) and a row surfacing as a value `{ id, path }`; **a projection may not overwrite the envelope** — `select id, path` is simply the envelope (no duplicate columns), and any other projection whose output key would be `id` or `path` (`select data.path`, `select path: doc.layer`) is `filter_invalid` "projection `path` collides with the hit envelope — alias it (`p: data.path`)" (`values` mode has no envelope and is exempt). Every tool result that renders a document, block, node or edge row names it the same way (`spec/surface` §2–§4): `docs_read`/`docs_read_at`/`docs_get_many.items[]`/`read_ref` `{ id, path, rev, properties, raw, ids?, hashes?, parents? }` with `properties.computed` keyed `title`/`tags`; `blocks_get`/`blocks_get_many`/`read_ref` (block) `{ id, type, text, raw, hash, attrs, label, ordinal, depth, parent_id, children }`; `graph.documents[]`/`frontier[]` `{ id, path, degree, frontier, …select }` (an `id`/`path` selection collapses onto the envelope, any other bare name is its own column, an expression is `sel_<i>`), `graph.edges[]` `{ id, doc_id, block_id, via_id, dst_id, dst_path, uri, dst_kind, predicate, provenance, anchor, field }`; `text_search.hits[]` `{ id, doc_id, path, type, text, score }`; `resolve[]` `{ id, locator, preview, evidence }`; `docs_list.items[]` and `docs_tree` doc entries `{ id, path, updated_at, blocks }` (dir entries `{ path, kind, docs, blocks, updated_at }`); every `revisions[]` (`apply`, the mutating tools, `changes_since` digests) `{ id, path, hash }`; `docs_history` `{ id, path, deleted, currentRev, versions: [{ rev, seq, commit, updated_at, origin, actor, hash, isCurrent }] }`; `docs_create`/`docs_move`/`docs_delete`/`docs_set_meta`/`observe`/`observe_many[]`/`observe_delete` `{ id, path, … }`; `docs_move.dangling[]` and `links_stale.stale[]` as edge rows `{ doc_id, path, block_id, … }` (`links_stale.summary.bySource[].path`); `diff[]` `{ kind, id, before?, after? }`; `diff_unified` `{ id, path, from, to, diff }`; `links_retarget`/`links_repair` `hits[]` `{ id, path, oldRaw, newRaw }`; `blocks_update` `{ id, ids, … }`; `docs_plan_update`/`docs_update` opset `target: { id, path }`, `precondition: { id, path, baseRevision, hash }`; `repos_status` `{ id, slug, … }`; error data `stale_expectation.current { hash, markdown }`, `stale_plan.current { revision, hash }`, `ambiguous_heading.candidates[{ id, doc_id }]`. Role keys keep their names (`rev`, `from`/`to`, `before`/`after`, `locator`, `baseRevision`, `cursor`, `expected_content_hash`). Unchanged: `blocks_history[]`, `results[].ids/removed/mergedInto`, `graph.roots[]`, `blocks_get_many.unresolved[]`, `docs_get_many.errors[].ref`, `retargeted{}`, the `diffs{}` keys, every cursor (the keyset carries values, so a 2.x cursor stays valid), `version`, `repos`, `sync_status`, and `spec/store`'s own observe outcome `{ doc, commit, rev }`.

**Language renames from 2.x (both engines, byte-identical):** `$id`→`id`, `$path`→`path`, `$updated_at`→`updated_at`, `$title`→`title` (computed; `data.title` for the authored key), `$tags`→`tags` (now authored ∪ hashtags; `data.tags` for the authored list), `^$id`→`^id`; `$body` → `raw` (a block's `raw` is its raw source bytes, not its text — `text` stays a field), `$content_hash` → `hash`; blocks `$doc` → `doc_id`, `$ordinal`/`$depth` → `ordinal`/`depth` (they collided with the `follow` recursion intrinsics; inside a `follow` `$depth` is always the walk's); nodes `$doc_id`/`$block_id` → `doc_id`/`block_id`, the `$node_id` synonym dropped; edges `$src` → `doc_id`, `$src_block` → `block_id`, `$via` → `via_id`, `$dst` → `dst_id`, `$dst_path` → `dst_path`, `$dst_uri` → `uri`, `src_field` → `field`, `$from_commit` removed (a query sees open edges only; the commit is history). **Foreign-key elimination** in both planners: `doc.id`/`doc.path` on a block, node or edge and `block.id`/`block.path`/`block.doc_id` on a node read the row's own FK column (or the scan's joined column) with no owner lookup — in SQL `b.doc_id`/`e.src_doc`/`n.block_id` — so `doc.id` and `doc_id` cost the same statement. The `query_syntax` text, both attribute switches and both translators carry the rule as a comment.

**Arguments (`spec/surface` §4 "Arguments", normative) and the catalog:** a tool's prefix names the row kind it addresses and `id` / `path` in its arguments are that kind's attributes — every `docs_*` tool that took `doc` (id-or-path) and/or `path` takes `id?` / `path?` (at least one; both must name the same document, else `filter_invalid` "id "…" and path "…" name different documents"); `blocks_update.block`, `blocks_split.block`, `node_set.node` → `id`; a document referenced from a tool of another kind is the foreign key — `diff`/`diff_unified` take `doc_id?` / `doc_path?`; list and role arguments keep their names (`ids`, `docs`, `roots`, `ref`, `to`, `blocks`, `at`, `docs_tree.path`, `*.path_glob`, `docs_create.path`, the `observe*` file paths); the kernel-op grammar (`apply.ops[].block/blocks/to/at/expect`) is spec/mutate's and is unchanged; the bare argument name `doc` no longer exists. Every call is shape-checked ahead of its handler, in both engines alike: an unknown name gets the nearest valid one ("unknown argument `q`; did you mean `query`?"; the retired names name their replacement — "`doc` is no longer an argument — pass `id` or `path`", `block`/`node` → `id`, `heading` → `section`, `markdown` → `text`), a missing one "`query` is required", a mistyped one "`limit` must be an integer", each followed by the tool's shape; `data: { reason, hint: "arguments" }`. Errors spell the attribute: `doc_missing` "no document with id or path "<value>"" (`doc_id`/`doc_path` tools: "with doc_id or doc_path"), `block_missing` "no block with id "…"", a node "no node with id …"; a `docs_*` call with neither locator is `filter_invalid` "pass id or path". **Fossil renames** (blocks used to be called nodes in the read tools): `nodes_get { doc?, path?, id, resolution? }` → `blocks_get { id, resolution? }`, `nodes_get_many { doc?, path?, ids, … }` → `blocks_get_many { ids, … }` (the document scope arguments are dropped — a block id is global), `history_node { id, limit? }` → `blocks_history { id, limit? }`; `node_set` keeps its name. **The append fold:** `sections_append` is removed — `docs_append { id? | path?, text, section?, dry_run? }` appends at the document's end or, with `section` (a heading's TEXT, resolved inside the named document; none → `parent_missing`, several → `ambiguous_heading` with `candidates[{ id, doc_id }]`), at the end of that section; the new `blocks_append { id, text, dry_run? }` appends INTO a block by what it is — a heading → the end of its section, a container → the end of its children, a leaf → `block_not_container` (`data: { id, type }`). `omg append <block>` renders `blocks_append`. **Loud `semantic()`:** `semantic_unavailable` is `provider_unavailable` at the surface and in `omg query`/`run`; a configured provider whose model has embedded nothing in the repository is `provider_unavailable` too (`data: { provider, model }`) instead of path-ordered rows with no score. **Description parity:** `spec/surface/tool-descriptions.json` is the one source of the 46 tool descriptions; `scripts/gen-tool-descriptions.mjs` generates `crates/omgbase-surface/src/descriptions.rs` from it and both spec runners pin it.

**CLI 3.0:** every verb's `--json`/`--jsonl` carries the tool result verbatim, so the shapes above are the CLI's; `ls --ids` prints the ids (was the paths), `find -1`/`--ids` read `id`; the shell's row ref for `ls` is the `id` (label `path`), for `links` the far node's `doc_id` (`links` out/in rows `{ predicate, doc_id, kind, count, samples? | block_id }`); `.field` reads any projected key. Human renderings are unchanged.

**Lower specs that own a renamed shape take a major:** `spec/search` 2.0 (`text_search`/`resolve` hits), `spec/mutate` 2.0 (`revisions: [{ id, path, hash }]`, the opset `target`/`precondition`, `stale_expectation`/`stale_plan` `current.hash`), `spec/sync` 2.0 (the change-feed revision `{ id, path, hash }`; `@omgbase/sync` and `omgbase-sync`'s `McpEngineClient` read the new keys). `spec/store`, `spec/graph` and `spec/properties` are unchanged (the graph fixtures pin the `edges` table — `src_field` stays the column; the properties table keeps its computed `$title`/`$tags` rows, re-keyed only at the surface). `omgbase-store` is patched for the shapes it renders for the mutate and search layers. `@omgbase/oqx-syntax`'s omgbase host vocabulary lists the bare attributes per kind (for completion providers; its `$`-highlighting is OQX's own `$it`/`$key`/… only).

**Migration from 2.x.**

| 2.x | 3.0 |
| --- | --- |
| `$id`, `$path`, `$updated_at` in a query | `id`, `path`, `updated_at` |
| `$title`, `$tags` | `title` (computed), `tags` (authored ∪ hashtags); the authored keys alone: `data.title`, `data.tags` |
| `$body` (docs) / `$body` (blocks, the text) / `$content_hash` | `raw` / `text` / `hash` |
| `$doc`, `$ordinal`, `$depth` on blocks | `doc_id`, `ordinal`, `depth` |
| `$doc_id`, `$block_id`, `$node_id` on nodes | `doc_id`, `block_id`, `id` |
| `$src`, `$src_block`, `$via`, `$dst`, `$dst_path`, `$dst_uri`, `src_field`, `$from_commit` on edges | `doc_id`, `block_id`, `via_id`, `dst_id`, `dst_path`, `uri`, `field`, — (removed) |
| `^$id` / `0^$id` | `^id` / `0^id` |
| a bare `id`/`path` was "did you mean `$path`?" | the attribute; the author's key is `data.path` |
| `frontmatter.path` to force an authored key | still works; `data.path` is the merged read; all three handles now push down |
| `select $path` (duplicate `path` column) / `select id: …` overwriting the envelope | `select path` is the envelope; `select path: …`/`select data.path` must be aliased (`p: …`) |
| result readers: `docId`/`doc`/`blockId`/`repoId` → … | `id`; `path`/`srcPath` → `path`; `content`/`raw` → `raw`; `contentHash`/`content_hash`/`baseContentHash` → `hash`; `ts` on a doc row or version → `updated_at`; `placement.{parent,ordinal,depth}` → `parent_id`/`ordinal`/`depth`; `srcDoc`/`src` → `doc_id`, `srcBlock`/`block` → `block_id`, `dst` → `dst_id`, `dst_uri` → `uri`, `src_field` → `field`, `node` (CLI `links`) → `doc_id`; `properties.computed.$title/$tags` → `title`/`tags` |
| inputs: `doc: <ref>` on `docs_*` | `id: <d_ id>` or `path: <path>`; `doc` → `doc_id`/`doc_path` on `diff`/`diff_unified`; `block`/`node` → `id` on `blocks_update`/`blocks_split`/`node_set` |
| `nodes_get` / `nodes_get_many` / `history_node` | `blocks_get` / `blocks_get_many` / `blocks_history` (drop the `doc`/`path` scope) |
| `sections_append { heading: <id>, markdown }` / `{ heading: <text>, doc\|path, markdown }` | `blocks_append { id, text }` / `docs_append { id\|path, section: <text>, text }` |
| `semantic_unavailable` | `provider_unavailable` |
| `ls --ids` consumers that wanted paths | `--jsonl` and read `path` |
| cursors | nothing |

The graph-ui and live-tail demos read both generations and send both argument spellings by the server's `specs.surface`.
