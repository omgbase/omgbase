**Surface 3.0 / CLI 3.0 — the `$` rule: `$` marks exactly the engine-provided names that contend with user names, everything else is a plain field, and every tool result spells a row the way the language does.** A `$`-prefixed name is a name the engine adds to a namespace it shares with user-generated content — frontmatter keys and inline properties on a document, `attrs` keys on a block or node — prefixed so the author's field names keep priority and never collide. That bounds the vocabulary to `$id $path` on every row, `$raw $hash $updated_at` on docs and blocks, `$title $tags` on docs (`spec/surface` §1.2, the normative statement and table); a foreign key is named for what it is (`doc_id`, `block_id`, `via_id`, `dst_id`, `dst_path`, `uri`), a column is its column (`depth`, `ordinal`, `field`). **Same value, same name:** a result key carrying what a row attribute yields is spelled as that attribute (`docId`/`doc`/`path`/`content`/`contentHash`/`ts` → `$id`/`$path`/`$raw`/`$hash`/`$updated_at`), role keys keep their names (`rev`, `from`/`to`, `before`/`after`, `locator`, `baseRevision`, `cursor`, `expected_content_hash`), inputs are untouched (`doc`, `path`, `block`, `id`, `expect.content_hash`). The first half of 3.0 — the query hit envelope `{ $id, $path, …projection }`, a row-as-value `{ $id, $path }`, `$id`/`$path` projections collapsing onto the envelope, `id:`/`path:` as ordinary columns, the keyset cursor unchanged — shipped first and stands.

**Language (the query binding, both engines):** `$body` → `$raw` (a block's `$raw` is now its raw source bytes, not its text — `text` stays a field), `$content_hash` → `$hash`; blocks `$doc` → `doc_id`, `$ordinal`/`$depth` → `ordinal`/`depth` (they collided with the `follow` recursion intrinsics; the "inside a follow the walk's win" rule is deleted — `$depth` in a follow is always the walk's); nodes `$doc_id`/`$block_id` → `doc_id`/`block_id`, the `$node_id` synonym dropped; edges `$src` → `doc_id`, `$src_block` → `block_id`, `$via` → `via_id`, `$dst` → `dst_id`, `$dst_path` → `dst_path`, `$dst_uri` → `uri`, `src_field` → `field`, `$from_commit` removed (a query sees open edges only; the commit is history). The loud-error set for a bare docs basename is `id path updated_at hash raw`. **Foreign-key elimination** in both planners: `doc.$id`/`doc.$path` on a block, node or edge and `block.$id`/`block.$path`/`block.doc_id` on a node read the row's own FK column (or the scan's joined column) with no owner lookup — in memory a lazy owner row, in SQL `b.doc_id`/`e.src_doc`/`n.block_id` — so `doc.$id` and `doc_id` cost the same statement. The `query_syntax` text, both intrinsic switches and both loud-error checks carry the rationale as a comment.

**Tool results (every tool, both engines, byte-identical — `spec/surface` §2–§4 list each shape):** `docs_read`/`docs_read_at`/`docs_get_many.items[]`/`read_ref` `{ $id, $path, rev, properties, $raw, ids?, hashes?, parents? }` (the maps keep their id-keyed shape); `nodes_get`/`nodes_get_many`/`read_ref` (block) `{ $id, type, text, $raw, $hash, attrs, label, ordinal, depth, parent_id, children }` — `placement` flattened, `parent` → `parent_id`; `graph.documents[]`/`frontier[]` `{ $id, $path, degree, frontier, …select }` (a `$`-named selection keeps its `$` and collapses onto the envelope key), `graph.edges[]` `{ $id, doc_id, block_id, via_id, dst_id, dst_path, uri, dst_kind, predicate, provenance, anchor, field }` (gains `block_id`/`via_id`; the rename table is gone); `text_search.hits[]` `{ $id, doc_id, $path, type, text, score }`; `resolve[]` `{ $id, locator, preview, evidence }`; `docs_list.items[]` and `docs_tree` doc entries `{ $id, $path, $updated_at, blocks }` (entries gain `$id`; dir entries `{ $path, kind, docs, blocks, $updated_at }`; cursors unchanged); `changes_since.digests[].revisions[]` and every mutating tool's `revisions[]` `{ $id, $path, $hash }` (apply revisions gain the document's hash after the commit, so the two revision shapes are one); `docs_history` `{ $id, $path, deleted, currentRev, versions: [{ rev, seq, commit, $updated_at, origin, actor, $hash, isCurrent }] }`; `docs_create`/`docs_move`/`docs_delete`/`docs_set_meta`/`observe`/`observe_many[]`/`observe_delete` `{ $id, $path, … }`; `docs_move.dangling[]` and `links_stale.stale[]` as edge rows `{ doc_id, $path, block_id, … }` (`links_stale.summary.bySource[].$path`); `diff[]` `{ kind, $id, before?, after? }`; `diff_unified` `{ $id, $path, from, to, diff }`; `links_retarget`/`links_repair` `hits[]` `{ $id, $path, oldRaw, newRaw }`; `blocks_update` `{ $id, ids, … }`; `docs_plan_update`/`docs_update` opset `target: { $id, $path }`, `precondition: { $id, $path, baseRevision, $hash }`; `repos_status` `{ $id, slug, … }`; error data `stale_expectation.current { $hash, markdown }`, `stale_plan.current { revision, $hash }`, `ambiguous_heading.candidates[{ $id, doc_id }]`. Unchanged: `history_node[]`, `results[].ids/removed/mergedInto`, `graph.roots[]`, `nodes_get_many.unresolved[]`, `docs_get_many.errors[].ref`, `retargeted{}`, the `diffs{}` keys, every cursor, every input, `version`, `repos`, `sync_status`, and `spec/store`'s own observe outcome `{ doc, commit, rev }`.

**CLI 3.0:** every verb's `--json`/`--jsonl` carries the tool result verbatim, so the shapes above are the CLI's; `ls --ids` prints the `$id`s (was the paths), `find -1`/`--ids` read `$id`; the shell's row ref for `ls` is the `$id` (label `$path`), for `links` the far node's `doc_id` (`links` out/in rows `{ predicate, doc_id, kind, count, samples? | block_id }`); `.field` on a ref admits the new names. Human renderings are unchanged.

**Lower specs that own a renamed shape take a major:** `spec/search` 2.0 (`text_search`/`resolve` hits), `spec/mutate` 2.0 (`revisions: [{ $id, $path, $hash }]`, the opset `target`/`precondition`, `stale_expectation`/`stale_plan` `current.$hash`), `spec/sync` 2.0 (the change-feed revision `{ $id, $path, $hash }`; `@omgbase/sync` and `omgbase-sync`'s `McpEngineClient` read the new keys). `spec/store` and `spec/graph` are unchanged (the graph fixtures pin the `edges` table — the `src_field` column stays the column; §6 notes the surface's names). `omgbase-store` is patched for the shapes it renders for the mutate and search layers.

**Batch 2 (2026-10-11, Brendan's decisions — the catalog's arguments, two fossils, the append fold, loud `semantic()`, description parity).** *Arguments (`spec/surface` §4 "Arguments", normative):* a tool's prefix names the row kind it addresses and `id` / `path` in its arguments are that kind's attributes — every `docs_*` tool that took `doc` (id-or-path) and/or `path` now takes `id?` / `path?` (at least one; both must name the same document, else `filter_invalid` "id "…" and path "…" name different documents"); `blocks_update.block`, `blocks_split.block`, `node_set.node` → `id`; a document referenced from a tool of another kind is the foreign key — `diff`/`diff_unified` take `doc_id?` / `doc_path?`; list and role arguments keep their names (`ids`, `docs`, `roots`, `ref`, `to`, `blocks`, `at`, `docs_tree.path`, `*.path_glob`, `docs_create.path`, the `observe*` file paths), the kernel-op grammar (`apply.ops[].block/blocks/to/at/expect`) is spec/mutate's and is unchanged, and the bare argument name `doc` no longer exists. The names are bare (not `$id`/`$path`) because the attributes themselves are becoming bare in the follow-up batch (surface 3.0 attribute flip). Every call is shape-checked ahead of its handler, in both engines alike (`mcp/arguments.ts`, `omgbase-surface::arguments`; the reference replaces the SDK's `tools/call` handler so the failure is the engine's `filter_invalid`, never the SDK's validation text): an unknown name gets the nearest valid one ("unknown argument `q`; did you mean `query`?", Levenshtein ≤ 2 or a prefix; the retired names name their replacement — "`doc` is no longer an argument — pass `id` or `path`", `block`/`node` → `id`, `heading` → `section`, `markdown` → `text`), a missing one "`query` is required", a mistyped one "`limit` must be an integer", each followed by the tool's shape ("(docs_read takes id?, include_ids?, path?, repo?)"); `data: { reason, hint: "arguments" }`. Errors that refer to a row's identity spell the attribute: `doc_missing` "no document with id or path "<value>"" (`doc_id`/`doc_path` tools: "with doc_id or doc_path"), the argument as given in `data`; `block_missing` "no block with id "…"", a node "no node with id …"; a `docs_*` call with neither locator is `filter_invalid` "pass id or path". *Fossil renames* (blocks used to be called nodes in the read tools; `nodes` is the extracted-entity row kind): `nodes_get { doc?, path?, id, resolution? }` → `blocks_get { id, resolution? }` and `nodes_get_many { doc?, path?, ids, … }` → `blocks_get_many { ids, … }` — the document scope arguments are dropped (a block id is global and names its document), `history_node { id, limit? }` → `blocks_history { id, limit? }`; `node_set` keeps its name (the one tool that addresses `nodes` rows). *The append fold:* `sections_append` is removed — appending is a document-level act or an into-a-block act: `docs_append { id? | path?, text, section?, dry_run? }` appends at the document's end or, with `section` (a heading's TEXT, `"Setup"` / `"## Setup"`, resolved inside the named document), at the end of that section (no such heading → `parent_missing` "no heading "…" in /<path>", the text spelled twice → `ambiguous_heading` with `candidates[{ $id, doc_id }]`), and the new `blocks_append { id, text, dry_run? }` appends INTO a block by what it is — a heading → the end of its section, a container (list, item, task, blockquote, table) → the end of its children, a leaf → the new error `block_not_container` (`data: { id, type }`, pointing at `blocks_insert … at.after`); the repo-wide heading-text lookup is gone with the union argument; `docs_append` gains `dry_run?`. `omg append <block>` renders `blocks_append` (its local path branches the same way). *Loud `semantic()`:* the code `semantic_unavailable` is `provider_unavailable` at the surface and in `omg query`/`run` (`spec/search`'s own `semantic_unavailable` for the embedding layer stays), `data: { provider: null }` and a message naming what to configure; a configured provider whose model has embedded nothing in the repository is `provider_unavailable` too (`data: { provider, model }`, "run omg embed drain") instead of every row scoring null and the result coming back path-ordered with no score; `ServerContext.embedProvider` / `Surface::with_provider_name` carry the provider's name for it. *`frontmatter.$x`:* an authored `$`-prefixed key is stored and reached through the `frontmatter`/`inline` handles and `entries(frontmatter)` in both engines already (the bare `$version` is the engine's namespace) — no engine or `spec/properties` change, pinned by `reads::arguments`. *Description parity:* `spec/surface/tool-descriptions.json` (written by the reference under `SURFACE_SPEC_UPDATE=1`) is the one source of the 46 tool descriptions; `scripts/gen-tool-descriptions.mjs` generates `crates/omgbase-surface/src/descriptions.rs` from it and both engines' spec runners pin it, so every description is byte-identical (before, only `query` and eight re-keyed ones were). *Fixtures (§6):* the surface's own errors — those whose `data` names the argument it could not honor or carry `hint: "arguments"` — now record their `message`, so both engines must spell them alike; two new `reads.json` cases (`arguments`, `append-into-blocks`). The demos (graph-ui, live-tail) send `id`/`path` (and `doc_id`/`doc_path`) to a 3.0 server and `doc` to an earlier one.

**Migration:** rename in queries — `$body` → `$raw`, `$content_hash` → `$hash`, `$doc` → `doc_id`, `$ordinal`/`$depth` on blocks → `ordinal`/`depth`, `$doc_id`/`$block_id`/`$node_id` → `doc_id`/`block_id`/`$id`, `$src`/`$dst`/`$src_block`/`$via`/`$dst_path`/`$dst_uri`/`src_field` → `doc_id`/`dst_id`/`block_id`/`via_id`/`dst_path`/`uri`/`field`, drop `$from_commit`; in result readers — `docId`/`doc`/`id`/`blockId`/`repoId` → `$id`, `path`/`srcPath` → `$path`, `content`/`raw` → `$raw`, `contentHash`/`content_hash`/`baseContentHash` → `$hash`, `ts` on a doc row/version → `$updated_at`, `placement.{parent,ordinal,depth}` → `parent_id`/`ordinal`/`depth`, `srcDoc`/`src` → `doc_id`, `srcBlock`/`block` → `block_id`, `dst` → `dst_id`, `dst_uri` → `uri`, `src_field` → `field`, `node` (CLI `links`) → `doc_id`; `ls --ids` consumers that wanted paths use `--jsonl` and read `$path`. Cursors need nothing. Inputs (batch 2): `doc: <ref>` → `id: <d_ id>` or `path: <path>` on every `docs_*` tool, `doc` → `doc_id`/`doc_path` on `diff`/`diff_unified`, `block`/`node` → `id` on `blocks_update`/`blocks_split`/`node_set`, `nodes_get`/`nodes_get_many`/`history_node` → `blocks_get`/`blocks_get_many`/`blocks_history` (drop the `doc`/`path` scope), `sections_append { heading: <id>, markdown }` → `blocks_append { id, text }`, `sections_append { heading: <text>, doc|path, markdown }` → `docs_append { id|path, section: <text>, text }`, `semantic_unavailable` → `provider_unavailable` in error handlers. The graph-ui and live-tail demos read both generations and send both argument spellings by the server's `specs.surface`. `@omgbase/oqx-syntax`'s omgbase host vocabulary (`OMGBASE.intrinsics`, for completion providers) lists the 3.0 `$` names and drops the removed `$repo`.
