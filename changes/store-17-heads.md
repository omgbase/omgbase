Store 17.0, slice 3a of the modular-core program (TypeScript reference + spec; the Rust twin follows in its own round — a store major ships both engines together, and until it lands a 17.0 database is unreadable by the published Rust binary). The current state is self-contained: `docs.head` is the head token the core mints on every change to a document — content, structure, path or liveness (D1; `current_rev` renamed), `docs.frontmatter_raw` and `blocks.raw`/`trivia` hold the bytes inline (D10: `blobs` is entirely the recorder's; no current read touches it or the delta resolver), `created_at`/`updated_at`/`deleted_at` on `docs` and `blocks` replace the `revisions×commits`/`block_changes×commits` joins and the `created_commit`/`deleted_commit` stamps (D6: `created_at` is the identity's birth, carried through the pool's new `created_at` and across cross-document moves; `updated_at` the entity's own last change), and a `docs_move` is a transition — a new head and, with legacy capture on, a revision of the unchanged tree at the new path; the Receipt and the plan preview list the moved document first (D11). Migration 17 rebuilds `docs`, `blocks` and `resurrection_pool` from the 16.x history tables (the frontmatter resolved once through the recorder, the bytes from `blobs` by hash, the timestamps from the joins). `spec/store` 17.0: the DDL, §3.4 step 17, §5.4 restated as the core's steps plus a capture step 15, §5.6, §6.1, §7, §8 (C1–C7 + H1/H3 — I3 restated as the recorder's capture *agreeing* with the head), `migrations::v16-to-v17-heads-inline-bytes-time`; every store/mutate/sync/surface/cli fixture that projects the renamed columns or gains a revision on a move regenerated. `doctor` renders `head present` / `capture complete`. `HistoryRecorder` gains `frontmatterAtRevision`, loses `currentFrontmatterRaw` and `movePath`; `blockRaw(store, blockId)` takes the block id; `reconstructContent`/`loadMutDoc`/the materializer render from the rows.

Slice 3b, identity claims (same major — M3/D5): the `id_claims(id, repo_id, prefix, minted_at, holders)` table, written by the core with the row that carries each id it mints (`d`, `b`, `r`, `x`, `e`, `rp`, `src`; `c`/`s` stay claimed by the recorder's own `commits`/`archives` rows, `cp` probes `checkpoints` until D4 retires it) and probed with one statement; `holders` bit 0 the core, bit 1 the recorder (set by its capture — `revisions`/`block_changes` — and released only by `history purge`), a row leaving only when no holder remains. The retention squash deletes every `block_changes` row of a wholly archived commit (the earliest-row rule of 15.0 is retired; `block_changes` is a pure projection and `rebuild-index` re-derives the whole table). `resurrection_pool.deleted_commit` → `deleted_at`, `expires_ts = deleted_at + 30 days` anchored on the row (I6 restated). The claims prune: `omg gc` releases the core's hold on claims older than `identity.claims_retain_days` (a new setting, default null = never) that name no core row and deletes those left with no holder — a pruned id MAY be re-minted on a repository without history, the documented consequence; `GcResult`/`gc --json` gain `claimsReleased` (the human line a `, <n> id claims released` suffix when non-zero); `doctor --size` gains the top-level `id_claims` count and an `id claims  <n> ids claimed` line. Migration 17 extended in place (17.0 is unreleased): the pool rebuild writes `deleted_at`, `id_claims` is created and backfilled from every id the current rows and the history still name (bit 1 where a history row names it); a database a 3a build already moved to 17 finishes the identity half on open. `IdentityClaims` is `claim(prefix, id, repoId, mintedAt)` / `hold(ids)` / `isClaimed` / `prune(now)` / `count()` (`IdClaims` replaces `TableUnionClaims`); `maintainEdges` takes `ts`; `runGc` takes `now`. `spec/store` §2.1 rewritten over the table (+ §3, §5.4, §5.6, §7, new §7.3, §8 C5/C6/H6, §9.4, §10); fixtures: `claims.json` new, every observation case gains an `id_claims` projection, the pool's `deleted_at`, the retention cases' squashed `block_changes` rows, the gc outcome's `claims_released`; `spec/mutate`/`spec/sync` pool rows, `spec/surface`/`spec/cli` squash counts, `spec/cli` `doctor --size` and `gc --json` regenerated. The Rust twin follows in its own round.

Slice 3c, self-contained recovery payloads (same major — M4): a `pending_materializations` row carries what its replay needs and nothing a history table has to answer — `head` (the token whose bytes it renders; replaces `rev_id`, no foreign key), `rendered_hash`, `prior_hash` (the bytes the engine itself last wrote at the path — the `file_hash` the commit validated the file against, captured at commit time; NULL for a created document) and `created_at`, with `commit_id`'s foreign key gone. The materializer renders from the current rows (`reconstruct`) and recognises the engine's own stale file by `prior_hash` instead of a `revisions` self-join; `recoverRepo` compares the disk to `docs.file_hash` and drops a kept row with the heal (file wins); the retention squash no longer pins a revision for a pending row (spec/store §7.1 rule 2 retired); `HistoryRecorder` loses `renderedHash`/`priorRenderedHash`; `materializeRow` takes no `priorHash` option. Supersession is pinned (spec/store §5.7, `spec/mutate` `materialize.json` +3 cases): a later write to a path that still owes a file replaces the row's target and keeps the earliest `prior_hash`, a rename carries the obligation of a write at `from_path` (that row goes), a remove drops the write; there is no cap on pending rows — unresolved recovery work is never discarded for a storage limit. Migration 17 extended in place: the table is rebuilt with `head = rev_id`, `prior_hash` = the previous revision's `rendered_hash` resolved once from the 16.x history, `created_at` = the commit's `ts`; a 3a/3b database at 17 finishes the step on open. New invariant C8 (a pending row names its document's current head and the bytes it renders to; a `remove` row a tombstoned document). `spec/store` §3.1, §3.4 step 17 (5), §5.4, §5.7, §7.1, §7.3, §8, §9.4, §10; `spec/mutate` §4 step 5, §9; `spec/sync` §4.3; fixtures regenerated (`migrations::v16-to-v17-…` gains two pending rows; the retention case that pinned a pending row's revision now archives it). The Rust twin follows in its own round.
