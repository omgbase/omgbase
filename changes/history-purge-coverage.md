History purge, the coverage-aware read states, the semantic lifecycle verbs and the feed-cap alert (modular-core Phase 4b — `spec/store` 17.2, `spec/surface` 6.2, `spec/cli` 5.2, `spec/sync` 4.2). **The read states** (`spec/surface` §3's decision table, D3): `docs_read { at }`, `docs_read_at`, `docs_diff`, `docs_diff_unified` and the CLI `diff` answer a revision token the recorder does not hold by the token's claim (`id_claims.minted_at`) and the repository's coverage intervals — `capability_unavailable { history, outside_coverage, rev, coverage_from, fix? }` for a token minted while capture was off, `{ history, pruned, rev, fix? }` for one minted inside coverage whose row was purged, `disabled`/`unavailable` as 4a, `target_missing` for a token nobody minted or another document's; `docs_history` always lists the current head with `retained: true|false` and carries the repository's `coverage` (resolution 11; never `disabled`); the `_revisions` relation and `^revisions` carry the capability hint. **`omg history purge [--before <ts>]`** (`spec/store` §7.6): the recorder's rows leave per commit — a live head's revision stays while capture is on, the first retained revision after a cut is re-checkpointed, open edge intervals are re-anchored at the earliest retained commit, the recorder's id holds are released on what nothing names (the live set keeps them while capture is on), and the bundle's tables are dropped automatically when no repository is enabled and nothing is left; coverage is NOT rewritten (it is the record `pruned` rests on); receipt `{ purged: { <table>: n }, claims_released, coverage, tables_dropped }`. **`omg embed enable [--provider <p>] | disable`** (`spec/store` §5.10) own the semantic manifest row; a settings write re-derives the row only when the effective `embedding.provider` CHANGED, so a `disable` is sticky across unrelated writes (through 17.1 every settings write re-derived it, and `ensureRepo` re-derived it on every open); a repository switched off with a provider configured refuses `semantic()`, `blocks_resolve`'s vector leg and `embed status|drain` with `capability_unavailable { semantic, disabled, fix: "omg embed enable" }` while `find` is FTS-only. **`feed_capped`** (`spec/store` §5.8): the write-time cap raises it with `{ pruned, oldest, head }`, a gc whose cap pass prunes nothing clears it; `doctor --size` prints the feed-cap advice from the alert.
