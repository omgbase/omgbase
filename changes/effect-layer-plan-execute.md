The Effect layer (ADR-021; `spec/mutate` 2.3 §11 "Effects and plans", `spec/surface` 3.1): nine public effects — `create`, `insert`, `set`, `unset`, `move`, `remove`, `split`, `merge`, `retarget` — over typed targets (`document`, `block`, `node`, derived `section {heading_id}`) with `field` spellings (`frontmatter.<key>`, `content`, `markdown`, `attrs.checked`, node `value`) and `expect` guards, lowered deterministically by a planner tier to the six kernel ops, `set_frontmatter` and the document operations (nothing added to the kernel). Three new verbs: `plan { effects }` returns a frozen, serializable plan (`version`, `planner_v`, resolved effects, lowered opset incl. creates/moves/tombstones, preconditions, symbolic `$new.n` identities, `plan_id` = sha256 of canonical JSON over the executable core, `preview` excluded) and writes nothing — a dry run no longer burns block ids; `execute { plan }` commits exactly that plan with its preconditions re-validated inside the transaction (`stale_plan`, `unsupported_plan_version`, `plan_mismatch` if the plan was edited) or `execute { plan_id, effects }` re-plans and commits only on digest equality; `apply` gains `effects` (exclusive with the legacy `ops`) = plan + execute in one lock scope and transaction, `dry_run` returning the plan. The planner rejects contradictory effects by focus kind — scalar (one write per plan; identical values dedupe), positional (ordered), identity (nothing after a `remove`, or on a descendant of a re-parsed block) — as `conflicting_effects { effects: [i, j], focus }` before anything is touched; `execute` does no analysis. The receipt maps `$new.n` to the minted ids. Effect-driven commits record ADR-003's intent in `commits.ops` (`{ v, plan_id, effects }`); legacy writes keep `ops` NULL. New fixture suite `spec/mutate/cases/effects.json` (33 cases incl. digest vectors) and three interop cases pin both engines to the same bytes and the same `plan_id`. The 21 existing tools are unchanged in this release; they become `apply` sugar in the migration that follows. Parity note: `omgbase-mutate` enables `serde_json`'s `float_roundtrip` feature so an over-u64 integer literal in an effect parses exactly as V8 does — without it the two engines would digest the same plan differently.
