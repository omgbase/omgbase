Modular core, Phase 2 (TypeScript half): the semantic layer is extracted behind `SemanticProvider`.

- **Layout.** The semantic bundle moves from `search/` to `src/semantic/` (`embeddings`, `tasks`, `vector`, `drain`, `external`, `provider`, the new `indexer`, `cache`, `advice`, `vec`); `search/` keeps the lexical FTS parts (`text`, `fts-query`) and the fusion ranker (`rrf`, `resolve`), whose vector leg now goes through the capability. The `cosine` SQL function is registered by the provider, not the store; the size report's vector advice, `semantic()` / `order by semantic(…)`, `blocks_resolve`'s hybrid leg, `omg status`'s queue depth and the drain all go through `SemanticProvider`. The dependency-direction test and the eslint rule bite on the whole of `semantic/**` for `core/**`, `mutate/**`, `sync/**`, `oqx-js/**`, `reconcile/**`, `mcp/**`, `search/**`, `graph/**` and `format/**`, and a new check proves no SQL outside the bundle names `embeddings`/`doc_embeddings`.
- **Compositions.** `coreCapabilities` (recorder + claims, no semantic module) beside `defaultCapabilities`; `envCapabilities()` selects by `OMGBASE_CAPABILITIES=core|full`, and both `Store` (when no factory is named) and `Workspace` use it — so every fixture suite and every `omg` verb can run core-only. A new `CapabilityUnavailable` error renders as `capability_unavailable { capability: "semantic", state: "disabled" | "unavailable", fix?, provider?, reason? }` (retriable only for `unavailable`): raised by `semantic()`, the ranker's vector leg, the `query`/`graph`/`blocks_resolve` tools and the `embed` verb when the store has no semantic module (`disabled`), and by the MCP server when the host reports a configured embedder it could not start (`ServerContext.semanticUnavailable`, `unavailable`). The full composition with no provider configured keeps the spec-pinned `provider_unavailable`.
- **Discovery.** `version` gains `capabilities: { history: { state }, semantic: { state } }` after `profile`; the semantic state is derived from the repository's `embedding.provider` setting (`enabled` iff configured; `unavailable` when configured but failed to start; `disabled` otherwise, a module-less store included) — never from stored vectors. `capabilityStates`/`semanticState` are exported.
- **Indexer.** The drain is a feed consumer with an explicit watermark (`sync_state` row under the `$semantic` sentinel source: index identity `{ model, dims, chunking }` + `processed_seq`): bootstrap from a consistent snapshot when there is none, catch-up (document pass restricted to the documents the feed names plus those whose blocks were re-embedded) from it, full rescan + cleanup on an identity change, an expired cursor, no feed, or `--prune`. A tombstoned document's vectors are pruned on every pass; a late result is never published (the worker compares the block's / document's current hash before writing; `EmbedResult.stale`). `SemanticProvider.drain/freshness/staleCount/scorer/sizeAdvice` are new; `omg embed status` reports the watermark; `omg embed drain` runs the indexer.
