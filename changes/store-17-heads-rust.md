The Rust twin of store 17.0 slice 3a (`changes/store-17-heads.md` is the TypeScript reference's note; a store major ships both engines together). `omgbase-store` reads and writes a 17.0 database byte for byte as the reference does: `schema.rs` at 17 with migration step 17 — the three `rowid`-preserving rebuilds of `docs`, `blocks` and `resurrection_pool` under `foreign_keys = OFF`, backfilled from the 16.x history tables (the live heads' frontmatter resolved once through the recorder's new `frontmatter_at_revision`, the block bytes from `blobs` by hash — a missing blob aborts — the timestamps from the `revisions × commits` / `block_changes × commits` joins), and an 18 refused; `observe.rs` mints the head (`docs.head`, D1) at the point the recorder's revision row was minted through 16.x and hands it to `HistoryRecorder::record_revision` (`RevisionTransition.head`; `record_move` is gone), writes `docs.frontmatter_raw` and `blocks.raw`/`trivia` inline (D10) and the `created_at`/`updated_at`/`deleted_at` carry rules (D6: carried on `same`, the pool's `created_at` on resurrection, the evicted foreign row's across a cross-document move; a tombstone sets `deleted_at`/`updated_at` and keeps the head); every current read — `reconstruct`, `block_raw(conn, block_id)`, `load_mut_doc`, `load_old_match_blocks`, the macros' `links_repair` scan over `instr(bl.raw, ?)`, `inbound_links_to`, the retarget planner, the materializer's `bytes_for` — comes from the rows and never from `blobs` or the delta resolver; `move_path_in` is a transition (D11: a new head, `UPDATE docs SET path, head, updated_at`, the unchanged tree captured as a revision at the new path — skipped when the same request also rewrites the document — the Receipt and the plan preview listing the moved document first, the `rename` pending row carrying the new head and `file_hash`); `changes_since` finds deleted paths by `docs.deleted_at = commits.ts` within the repo; the `r` prefix is also claimed by `docs.head`. `omgbase-surface`: `_updated_at`/`_created_at` are the rows' own columns on docs and blocks (a block's pushable at last), OQX `_raw` reads `blocks.raw`, `block_raw` takes the block id, every live-row guard says `deleted_at IS NULL`. `omgbase-sync`: the same column names in `repos_status`, recovery, freshness and the engine's `read_doc`. The binary's `doctor` renders `head present` / `capture complete`. Every spec runner (store incl. `migrations::v16-to-v17-heads-inline-bytes-time`, mutate, surface, sync, cli, interop across the four pairings) is green against the 17.0 fixtures.
