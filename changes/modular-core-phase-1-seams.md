Modular-core Phase 1, the TypeScript half (docs/modular-core/README.md §5 "Dependency-direction check", §6 "Phase 2 opener"): the history and semantic behaviour wrapped behind interfaces with today's code as the one implementation, and a dependency-direction check so no new import reaches a concrete history/semantic module from the current-state layers. No behaviour, schema or fixture changes — every existing test passes unchanged; the bump is `patch` because `@omgbase/core`'s public surface GROWS (the capability types, `defaultCapabilities`, `StoreOptions.capabilities`, `Store.capabilities`, the registry) while nothing it did changes.

- `src/core/capabilities/` — `HistoryRecorder` (the write half every write entry point calls per committed transition — `newCommit`, `captureRevision` with the id-assigned tree, frontmatter raw, rendered hash, path and commit; `recordDispositions`; `movePath` — the current-state-through-history reads `currentFrontmatterRaw`/`renderedHash`/`priorRenderedHash`, the surface's `readAtRevision`/`blocksHistory`/`diffBlocks`/`diffUnified`/`docDiffUnified`/`docsHistory`/`changesSince`, and `markReachable` + the retention/archive entry points), `SemanticProvider` (`blockContexts`, `blockVector`, `docVector`, `available`, the drain's `embed`/`embedDocs`/`pruneForeign`, `vectorSearch`/`docVectorSearch`), `IdentityClaims` (`claim`, `isClaimed`), the `Capabilities` composition `{ history | null, semantic | null, claims }`, and the defaults `HistoryRecorderImpl`, `SemanticProviderImpl`, `TableUnionClaims` (the `ID_TABLES` union, moved from `Store`). `Store` takes `capabilities?: (store) => Capabilities` and binds the set to its connection (`capabilitiesOf(db)`, `requireHistory(db)`, `semanticOf(db)`); `Workspace` names `defaultCapabilities`; a bare `new Store()` installs the same defaults.
- Routed through the seams: `ingestFile`/`ingestInto` (the commit row, steps 0–2 and step 10), `runPhases` (the commit row, the move's revision path and rendered hash), `tombstoneObservedDeletion`, `currentFrontmatterRaw`, `readDocumentAtRevision` (its body is `graph/history.ts`'s `reconstructAtRevision`), the materializer's render and prior-bytes rule, `sweepUnreachable`'s mark, the size report's archived/retention lines, OQX `semantic()`'s vector reads, the MCP history tools and the `semantic` gate. The mint oracle is `claims.isClaimed`.
- `search/cel/compile.ts` deleted (D9: dead, no importer); `FilterInvalid` lives in `core/filter-invalid.ts` (`search/cel/parser.ts` re-exports it), `SemanticVec` in the capability types.
- The dependency-direction check: `src/dependency-direction.test.ts` reads the import graph and fails on any import from `core/**` (except the seam), `mutate/**`, `sync/**`, `oqx-js/**`, `reconcile/**` into `graph/history.ts`, `core/store/{archive,retention,delta}.ts`, `search/{embeddings,vector,tasks,drain}.ts` or `search/cel/**` that `core/capabilities/import-allowlist.json` does not name (and on a listed edge that is no longer live — the list only shrinks); `eslint.config.js` carries the same rule for the editor. Before: 14 edges; after: the two allowlisted (`writers.ts` → `delta.ts`, `gc.ts` → `delta.ts`, each with its inventory row).
