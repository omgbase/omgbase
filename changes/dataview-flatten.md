`FLATTEN` is translated (it was the translator's last big refusal): `FLATTEN <expr> [AS name]` becomes OQX 0.25's `flatten <expr> as <name>`, several chaining in order, the name the `AS` or the field path's last segment (`FLATTEN file.tasks` binds `tasks`, Dataview's rule). The implicit fields map to the engine's collections — `file.tasks` / `file.lists` → `flatten blocks collect { where type == "task" | "list_item" } as t` (the task fields read through the bound name: `t.completed` → `t.checked`, `t.blockId` → `t.id`), `file.outlinks` / `file.inlinks` → `out_links collect { from dst }` / `in_links collect { from doc }` (the linked document's fields: `o.file.mtime` → `o.updated_at`), `file.tags` / `file.etags` / `file.aliases` → `tags collect { }` (the block keeps Dataview's "no tags, no row"), an authored field → itself (absent → one null row, as in Dataview). A `WHERE` after a `FLATTEN` is split at its top-level `&` into conjuncts: the page's go to the body `where`, one element's into that flatten's block (`WHERE t.completed` → `blocks collect { where type == "task" and checked }`; on an authored field through `list(…)`, warned), a conjunct mixing the two sides (or two bound names) is `unsupported` — the only split OQX's `where`-before-`flatten` order admits without changing the result. `SORT`, `LIMIT` and `GROUP BY` after a `FLATTEN` act on the flattened rows (`FLATTEN file.tags AS tag GROUP BY tag` is the tag census `flatten tags collect { } as tag group by key: tag`); `FLATTEN` after `GROUP BY` is refused (clause order). A `TASK` query with `FLATTEN file.tasks` is re-rooted at the page (`from docs flatten blocks … as t`, the task shape `path, task_id: t.id, text: t.text, checked: t.checked`; `RenderShape.task` now carries the aliases as strings). New capability flag `capabilities.flatten` (OQX ≥ 0.25, default true). `group by` is now printed through the AST builders too. Golden corpus 181 → 244 cases (64 flatten cases, every emitted query parsed whole by `@omgbase/oqx` 0.25 and round-tripped; every successful one also run against the alchemy corpus through the built CLI).
