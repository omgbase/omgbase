The Rust twin of history-optional (modular-core Phase 4a — `spec/store` 17.1, `spec/surface` 6.1, `spec/sync` 4.1, `spec/cli` 5.1), mirroring the TypeScript reference row for row. `omgbase-store`: a fresh database executes `schema.sql` alone and the opener's `apply_bundles` follows the composition (the semantic bundle with the module, the history bundle when any repository's `history` row is `enabled`); `manifest::{capture_for, history_reader, require_history_reader, writer_for, capture}` — a commit hands the recorder its rows only while the repository's row is `enabled`, every write site (`ingest_in`, `append_feed_row`, `maintain_edges`/`retarget_open_edges`, `move_path_in`) runs on an optional recorder under `capture()`, `require_writer` is called outside the transaction and clears `writer_refused` on every passing write; `enable_history` (the contracts' §1.14 baseline through `HistoryRecorder::baseline`) / `disable_history`, `Store::{enable_history, disable_history, create_repo_with, capture_for, history_reader, require_history_reader, set_history}`; `Capabilities::core_only()` carries no recorder and is what `OMGBASE_CAPABILITIES=core` opens (a test-only override — a core-only build); `Error::{HistoryUnavailable, HistoryDisabled { rev }, CaptureFailed { path, reason }}` with the reference's messages, a failing recorder rolls the member back (`BatchOutcome::Failed`, the `capture_failed` alert raised after the rollback, the api path fails the request); the seam gains `RevisionQueryRow` and `revision_rows`/`doc_revision_rows`/`has_revision`/`uncaptured_heads`/`baseline`; `tests/boundaries.rs` gains the history-SQL gate (no SQL under `src/core/` names a history table). `omgbase-surface`: `capability_unavailable { history, unavailable | disabled, rev?
