The Rust twin of modular core slice 5a-ii — migration fidelity (`spec/store` 17.4, `spec/sync` 4.4, `spec/cli` 5.4), mirroring the TypeScript reference row for row. **The legacy-bytes check** (`omgbase_store::legacy_bytes`): `unreproducible_docs` (per live document with a `file_hash`, `sha256(reconstruct) == file_hash`, bytewise path order), `legacy_bytes_suspected` (the cheap signature — a live top-level block with a NULL `trivia` and a later top-level sibling, or a `frontmatter_raw` without `frontmatter_trivia`), `refresh_legacy_bytes_alert` (the `legacy_bytes` `warning` with the pinned message and detail `{ docs, sample: [first 20 ids] }`, cleared when none is left), `legacy_bytes_active`; `schema::migrate_v17_legacy_bytes` runs it in full at the 16 → 17 step and behind the signature at the on-open finish of a 17.x database, after the manifest and tombstone steps; step 17 (2) rebuilds the FTS index once over the migrated rows when `blocks_fts` exists (`derived::fts_rebuild`); `read::reconstruct` decodes a BLOB-typed separator column as its UTF-8 text, as the reference's Buffer concatenation does. **The repair** (`omgbase_sync::legacy_bytes::repair_legacy_bytes`, `LegacyRepairOutcome`): the file's parse must match the rows positionally — shape, types, `raw`s, frontmatter raw — then only `blocks.trivia`/`trivia_hash`, `docs.leading_trivia`/`frontmatter_trivia` are rewritten in one transaction, rolled back when the rows still do not reproduce the file; no head, no feed row, no `updated_at`. The freshness sweep gains step 5 (gated on the active alert; a missing file stays listed, a diverged file is an ordinary re-ingest) and `SweepResult.repaired`; `changed` counts it. **The binary:** `doctor` gains `bytes reproducible` after `head present` (re-derived in full, the alert written to match) and its help summary names it; `sync --json` carries `repaired` and the human rendering prints a `repaired` line. **Runners:** the store and sync runners check C9 and A1's `legacy_bytes` rule and exempt alert-named documents from C1's reconstruct clause and H3's trivia clause; the sync runner runs the `sql`, `legacy_bytes` and `alerts` steps and projects `repaired` only when non-empty. Version pins: store 17.4, sync 4.4, cli 5.4.
