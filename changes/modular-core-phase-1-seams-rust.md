Modular core, Phase 1, Rust half (`docs/modular-core/README.md` §5 "Dependency-direction check"): the interfaces are isolated with no behaviour, schema or fixture change — every spec runner and the interop suite pass unchanged.

- **`omgbase-store` is three module trees and a composition root.** `src/core/` holds the current-state core (ids, the checking minter over an `IdentityClaims` oracle, time, order keys, `codec` — canonical attrs and hex, `writers` — the id-assigned body and the commit row's provenance, `observe`, `properties`, `graph`, `derived` — sections/FTS/the pool sweep, `read`, `text_search`, the `spec/mutate` host side, `materialize`, `size`, and the seams in `capabilities`); `src/history/` the recorder (`writers` — blobs, tree nodes, revisions, commits; `tree`, `delta`, `edit_script`, `feed` — the old `history` module, `read` — `read_at_revision`, `gc` — the revision-rooted mark and sweep, `retention`, `archive`); `src/semantic/` the provider (`search` minus `text_search`, the `cosine` scalar). Every pre-existing crate-root path still resolves (`omgbase_store::read::reconstruct`, `::archive::revision_body`, `::search::build_embed_tasks`, `::history::changes_since`, `::tree::from_hex`, …); nothing outside the crate had to change to compile.
- **Three traits in `core::capabilities`.** `HistoryRecorder` — what the recorder receives per committed transition (`new_commit`, `record_revision` → the head token, `record_dispositions`, `record_move`) and the history reads the store exposes (`read_at_revision`, `rendered_hash`, `previous_rendered_hash`, `changes_since`, `rebuild_projection`, `gc`, `gc_dry_run`, `count_same_dispositions`, `size_figures`, `retention_policy`, `retention_plan`, `export_history`, `attach_archive`, `detach_archive`, `list_archives`); `SemanticProvider` (`attach`, `available`, `block_vector`, `doc_vector`, `embed`, `embed_docs`, `prune_foreign`); `IdentityClaims` (`is_claimed`, `claim`). One default each — `history::Recorder`, `semantic::Provider`, `core::TableUnionClaims` — is today's code moved behind the trait, call for call. `Capabilities { history, semantic, claims }` is assembled by `Capabilities::standard()` on the crate root and passed down through the new `Store::open_with` / `Store::from_connection_with`; `Store::open*` keep their signatures and install the standard set, so no caller changed. `Store::history()` / `Store::semantic()` expose the capabilities.
- **Routed through the traits:** the observe commit's history half (the revision's place, frontmatter blob, tree and row; the dispositions), every `new_commit`, `docs_move`'s revision re-path, the materializer's `read_at_revision` and prior-bytes rule, `record_intent`'s rendered hashes, the mint oracle, `changes_since`, `docs_read { at }`, the GC mark and sweep, `rebuild-index --block-changes`, the size report's history figures, the retention/archive entry points; on the surface, `semantic(…)`'s vectors (`StoreContext::with_semantic_provider`) and the `provider_unavailable` gate (`require_rankable`); in the binary and the sync workspace, the store open path assembles `Capabilities::standard()` explicitly. Everything the core still reads from history through SQL carries a `// seam: <Trait>::<method> (Phase 3)` comment citing its inventory row.
- **The dependency-direction tests.** `crates/omgbase-store/tests/boundaries.rs`: no `crate::` path under `src/core/` reaches a name `lib.rs` re-exports from `history` or `semantic` (derived from `lib.rs`, so a renamed module cannot slip past), the semantic layer names nothing of history, and `boundary-allowlist.txt` lists what Phase 3 removes — one entry: `core/read.rs delta` (`current_frontmatter_raw` resolving the current frontmatter through `TreeResolver`, M1) — an entry that stops matching fails the test too. `crates/omgbase-surface/tests/boundaries.rs`: `context.rs`, `translate.rs`, `planner.rs` name no history/semantic item of the store.
