Modular core Phase 5a-ii — what the Phase 5 qualification found on copies of two real 16.x workspaces, fixed in the TypeScript reference (`spec/store` 17.4, `spec/sync` 4.4, `spec/cli` 5.4; the Rust twin follows):

- **Legacy bytes (F1).** A document ingested before the store kept block trivia (schema v6) has rows that do not reproduce its file — the 16.x reader already served it without the newlines between its blocks while the file and `docs.file_hash` were right, and migration 17 copied the rows as they were. The migration now runs a fidelity check (`sha256(reconstruct) == file_hash` per live document — in full at the 16 → 17 entry point, behind a cheap signature of legacy rows on every later open) and names the documents in a new `legacy_bytes` alert (`warning`; `<n> document(s) carry bytes the engine cannot reproduce from its rows (imported before block trivia was stored); omg sync repairs them from the files`; detail `{ docs, sample }`). `omg doctor` gains the check `bytes reproducible` and re-derives the alert; **`omg sync` repairs** every named document whose file is present and hashes to `file_hash` — the separator columns rewritten from the file's parse, every block keeps its id, the head stays, no commit, no revision — and reports them as `repaired` (the sweep result's new member; the `sync` human output's `repaired` line). A document whose file is gone stays listed. No new column (`spec/store` §5.11, §8 C9).
- **FTS orphans (F2).** The 16 → 17 migration rebuilds the FTS index over the new rows (a 16.x index may hold every block), and the 17.x finish step that deletes a 17.0–17.2 database's tombstoned `blocks` rows first purges the index entries it actually holds, so `doctor`'s `fts rows == live leaf blocks` is green on a migrated database.
- **`scripts/qualify/migrate-copy.mjs`**: the `--before-bin` refusal is recognised by its message whatever the exit status (omgbase 0.27.3 exits 0 under `--json`); a database without a `docs` table is reported `{ ok: false, reason }` with exit 2; the copy's `fs` sources are re-pointed at the copied tree (`--with-files` copies an outside root; every `omg` runs `--stale`) so nothing reaches the original directory; `--repair` runs `omg sync` on the copy and reports `repair: { legacy_bytes_before, repaired, remaining }`; the composition pass no longer counts AFTER's own `bytes_hash` as a composition difference.
