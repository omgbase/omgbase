Modular core, Phase 2, Rust half (`docs/modular-core/README.md` §6): semantic search is extracted behind the `SemanticProvider` capability, discovered per repository, with an explicit indexer watermark. No on-disk schema change: the `embeddings`/`doc_embeddings` DDL stays; what changed is that nothing outside `omgbase-store/src/semantic/` reads or writes a vector except through the trait.

- **Everything semantic behind the trait.** `SemanticProvider` grows `tables`, `vector_search`, `doc_vector_search`, `hybrid_search`, `resolve` (with a query vector), `drain` (the watermark-positioned indexer), `rebuild`, `freshness`, `queue`, `foreign`; the `impl Store` block of `semantic/search.rs` (`Store::drain`, `::vector_search`, `::hybrid_search`, `::resolve`, `::build_embed_tasks`, `::stale_blocks`, …) is gone — callers go through `Store::semantic()` / `Store::require_semantic()`. The §4 fusion over an FTS ranking and a vector ranking handed in (`fuse_and_boost`, the FTS-only `resolve`) moves to the core's `text_search` (it reads no vector), so `blocks_resolve` without a provider and `find --no-semantic` need no semantic bundle; the shapes the trait speaks in live in the core's new `semantic_shapes` (`VectorHit`, `HybridQuery`, `ResolveHit`, `DrainStats`, `DrainOutcome`, `IndexIdentity`, `SemanticFreshness`, `SemanticQueue`, …). The size report's embeddings advice takes the bundle's tables from the provider; a store without the bundle never emits it. `tests/boundaries.rs` (store and surface) gain the data boundary: no SQL under `src/core/` (except the byte accountant's category map in `size.rs`) and none in the surface names `embeddings`, `doc_embeddings` or `cosine(`; the surface's path check now covers `query.rs` and `select.rs` too.
- **Discovery and the manifest.** The semantic capability's state is `enabled` for a repository iff its effective settings name an `embedding.provider` (contracts §7 resolution 1; stored vectors are never consulted) — derived from the settings and the store together (`version`, `omg embed`/`status`); the module itself is a composition matter: the standard set carries it (a loaded module with nothing configured keeps the pinned `provider_unavailable`), `OMGBASE_CAPABILITIES=core` opens without it, and the MCP server marks it `unavailable` with the spawn failure's reason when the configured provider cannot start (`Store::detach_semantic`). `Capabilities` gains `semantic_fault`, `without_semantic()`, `with_semantic_fault()`, `from_env()` / `standard_from_env()` (`OMGBASE_CAPABILITIES=core` opens every store without the bundle — the fixture runners and the binary honour it); `Store::semantic_state()` / `history_state()` / `semantic_fault()`; `CapabilityState`. `version` gains `capabilities: { history: { state }, semantic: { state } }` after `profile` — the semantic state read against the repository's `embedding.provider` (`version_info_for`, `semantic_configured`) as well as at composition (pinned by a unit test as the literal `"capabilities":{"history":{"state":"enabled"},"semantic":{"state":"disabled"|"enabled"}}`); the shape-recorded `version` reads in `spec/surface` (`reads`, `examples`, `interop`) and `spec/cli` (`read::version-json`) gain the member. New error `capability_unavailable { capability: "semantic", state: "disabled" | "unavailable", provider?, reason?, fix? }` (retriable only for `unavailable`; messages and `data` byte for byte the reference's `core/capabilities/errors.ts`) from `query` with `semantic(…)`, `graph` with a semantic selector, the query-directed selectors and `blocks_resolve` when the store has no semantic capability (`disabled`) or the host's provider failed (`unavailable`); a store with the capability and no provider keeps `provider_unavailable` (the pinned 3.0 cases `interop::read-query`, `reads::errors-and-sourceless-writes`, `cli query::semantic-unavailable[-json]` are unchanged). Under `OMGBASE_CAPABILITIES=core` the surface runner rewrites those two pinned steps to the `disabled` envelope and reports how many it rewrote.
- **Bootstrap, catch-up, freshness, rebuild.** The indexer's watermark lives in the bundle's own bookkeeping row `sync_state (repo_id, source_id = '$semantic', path = '')` — `revision` the index identity `{ model, dims, chunking }`, `cursor` `{ processed_seq }` — byte for byte the reference's encoding, so a workspace served by both engines shares one watermark (no new DDL; the `capabilities` manifest table is Phase 3's). `drain` positions itself: no watermark or another index identity → **bootstrap** from one read snapshot of the head; the watermark behind the head → **catch-up** over the documents the feed (`Store::changes_since`) names since it, re-tasked by themselves (a task depends on its document alone), capped at 500 documents; a cursor beyond the head (restore, rebuild-from-files, pruned feed) or an oversized set → **rescan** plus the prune of the model's vectors whose entity is gone (S1: `embeddings.content_hash` no live `raw_hash`, `doc_embeddings.doc_id` not live; other models' rows stay `--prune`'s). Every pass sweeps gone document vectors; the watermark is written only after both halves succeeded; a document vector is written only while the document's head (`docs.current_rev`) is the one its task was built from (`DocEmbedStats.skipped`) — never a stale vector; block vectors are content-addressed and need no check. `rebuild` forces the rescan; `freshness` reports `processed_seq` vs `head` and whether the stored identity is the configured provider's. `omg embed status` shows the position (`freshness` in `--json`); `omg embed drain` reports `mode`, `processedSeq`, `docsRescanned`, `skipped`, `swept`; `status.embedQueue` is the trait's `queue`, or every embeddable live leaf when the capability is disabled (its pinned values are unchanged). The MCP and `sync --watch` drainers run the positioned drain.
- **Fixtures.** `spec/search`'s `drain` step stays the two spec'd passes (`embed` + `embed_docs`: `cached` counts every task, a tombstoned document's row lingers); the positioned drain is pinned by `semantic/provider.rs`'s unit tests (bootstrap → catch-up → fresh, the deleted document, the expired cursor's rescan, the model change, the late document vector). Every existing fixture passes unchanged apart from the `version` shapes above.
