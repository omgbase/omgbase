Modular-core Phase 6b, the Rust twin — **the remote half of the Git-backed history provider** (spec/store 17.6 §5.12, spec/surface 6.5, spec/cli 5.6, spec/sync 4.6), mirroring the TypeScript reference file by file. `omgbase-store`: the `HistoryVaultSink` seam (the vault as the remote half writes inbound content into it — a batch of `VaultChange`s applied as external edits through the observe path; the Rust seam also lends the connection, since a sink owns the store for the call), `remote_summary`/`remote_sync` on `HistoryProvider` (default `None`), `CheckpointResult.push` (`PushOutcome`: the receipt or `{ error }`), `PushResult`, `RemoteState`/`RemoteSummary`, `RemoteSyncResult`, `update_history_provider_config` (the row's `config` rewritten in place — state, coverage, versions and `writer_requires` untouched), providers held as shared handles (`Store::provider_handle`, `require_provider_handle`), the error codes `git_remote_diverged` and `git_merge_conflict` with the alerts' messages. `omgbase-git-adapter`: the remote binding `{ name, url, branch, push: off | on-checkpoint | periodic, fetch: off | periodic | webhook }` (`remote_config_for`, credentials refused), `GitRepo`'s remote plumbing with the reference's argv (`push --porcelain --quiet`, `fetch --quiet --no-tags`, `ls-remote`, `merge-base [--is-ancestor]`, `diff-tree -r -z --no-renames`, `ls-tree -r -z`, `rev-list --reverse`, multi-parent `commit-tree`), the `remote` module — `remote_set|unset|status`, `push_branch` (never `--force`; a rejection raises `git_remote_diverged`), `fetch_remote` (fast-forward through the sink; the tree-level three-way merge with one merge commit carrying `omgbase-merge`; conflicts kept as `<stem>.remote-<short>.md` sidecars under `git_merge_conflict`), `resolve_conflict`, the rewritten remote detected-stopped-alerted with push and fetch paused, `reconcile_remote` (`--rebase` replaying the unpushed commits byte for byte with the ids ref rebased alongside, `--merge`, `--adopt` with `<stem>.local-<short>.md` sidecars, `--fork`), `remote_sync` for the sweep and `push_after_checkpoint` — the ref names, alert codes, detail keys and messages byte for byte; the `ids` module (`refs/omgbase/ids`: one canonical-JSON id map per live document, a parallel chain with `omgbase-seq` and `omgbase-content`); the worker's no-op rule (a tree equal to its parent's writes no commit; the `$git` row advances) and resume rule (the row refines the tip's trailer when it names the same tip); the `$git` row's `pushed`; the `scheduler` (`every` synchronous in the mutation hook, a debounce timer coalescing a burst, `flush` at shutdown). `omgbase-sync`: the sweep's steps 7–8 (`run_provider_remote_sync` over `FsVaultSink` — files under the root as external edits, then `process_checkpoint` and the stat cache), `version.capabilities.history.remote`. `omgbase-surface`: the two error envelopes. `omgbase`: `history remote set|unset|status|resolve|reconcile`, `history push`, `history fetch`, `checkpoint`'s push line, the help card, the MCP host's checkpoint scheduler (notified by the catalog's mutation hook and the watcher's checkpoints).
