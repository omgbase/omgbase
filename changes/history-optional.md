History capture is optional (modular-core Phase 4a — `spec/store` 17.1, `spec/surface` 6.1, `spec/sync` 4.1, `spec/cli` 5.1). The history bundle's DDL follows the manifest: a fresh database holds the core and semantic bundles alone and the history tables appear when a repository's `history` row becomes `enabled` (`ensure_repo` with the recorder, `omg history enable`); a commit hands the recorder its rows only while the repository's row is `enabled` (`captureFor`), so a disabled repository writes the feed, heads, claims, pool and edges and no history row. New verbs `omg history enable [--best-effort]` / `omg history disable` (`spec/store` §5.9 — `enable` writes the contracts' baseline: one `import` feed row with a `changed` entry per live document under its existing head, a checkpoint revision for every head the recorder does not hold, the edge record reconciled; `disable` closes the coverage interval and leaves the rows), `omg source add --no-history`. `writer_requires` is reachable: a composition without the history module (`OMGBASE_CAPABILITIES=core`, now a test-only override that drops the recorder too) refuses a write on an enabled repository that requires capture, outside the transaction, under the `writer_refused` alert. A capture that throws rolls the member back (resolution 18): `capture_failed` alert and envelope, the batch goes on, the next sweep retries (`BatchResult.failed`). `version.capabilities` gains `history.coverage_from`/`writer_requires` and `semantic.model`; `docs_read { at: <current head> }` is served from the rows whatever the capture state (resolution 11) and the history tools raise `capability_unavailable { history, disabled | unavailable }`; the `revisions` root carries a capability hint when capture is off. No SQL outside the history bundle names a history table (the recorder's writers and collection moved to `core/store/history-writers.ts` / `history-gc.ts`; `dependency-direction.test.ts` enforces it). Fixtures: `spec/store` `schema::fresh` and five migration cases moved, `cases/history/capture.json` new; `spec/surface` `reads::orientation`, `changes-since-epoch-and-expiry`, `examples::ladders` moved, `reads::history-disabled` new; `spec/cli` the `status`/`sync` JSON cases and the `history`/`source` cards moved, six cases new. The Rust twin follows as its own change.
