## [3.0.0] - 2026-10-20

### Major
- **Surface 5.0 / mutate 4.0 / sync 3.0 / search 3.0 / graph 2.0 / CLI 5.0 — "underscore = engine": on every record kind a BARE name is a user-authored entry and an UNDERSCORE-prefixed name is engine-provided, however derived.** The `_` prefix declares an engine field on a record; the bare namespace is the user's on every record — docs, blocks, nodes, links, revisions and the root row alike, because any record may carry user data later. `$` stays OQX's (`$it $key $depth $stop $leaf $frontier $ordinal`); omgbase adds no `$` names. Collections stay bare (`from docs`, `^docs`, `0^docs`, `docs count { … }`, `entries(^$it)` yields `docs blocks nodes links revisions`) — `from` names a collection, not a row property — and so do the row functions in call position (`text("x")`, `semantic(…)`, `under(…)`, `refs(x)`, …): a call is never an entry read. The self aliases are gone (`doc` on a document, `block` on a block, `section` on a node): `$it` is the self; a bare `doc` is now an authored key like any other. **Arguments and effect targets that address an engine field spell it with the underscore, and there is no tolerance**: a bare `id`/`path`/`ids` argument is an argument error whose message names the `_` spelling and whose `data.fix` is the corrected call. The Rust twin (`omgbase-surface`, `omgbase-mutate`, `omgbase-sync`, `omgbase-search`, `omgbase-graph`, the `omgbase` binary) follows in a separate round: until it lands the Rust spec runners and the cross-engine interop suite (`spec/surface` §7, `interop.json`) are red by design.

  **The language (spec/surface §1.2).** Row names, 4.11 → 5.0:

  | kind | engine names (attributes · handles · relations), 5.0 | bare names |
  | --- | --- | --- |
  | docs | `_id _path _raw _hash _updated_at _created_at _title _tags _format` · `_data _frontmatter _inline` · `_blocks _nodes _out_links _in_links _revisions` | every authored property (frontmatter + inline by the property rule): `title`, `tags`, `id`, `path`, `data`, `doc`, `format` included — nothing is reserved |
  | blocks | `_id _path _doc_id _raw _hash _updated_at _created_at _type _text _attrs _depth _ordinal` · `_doc` · `_children _nodes _out_links _section` | an `attrs` key (`checked`, `level`, `lang`; `_attrs.<k>` ≡ `<k>`) |
  | nodes | `_id _path _doc_id _block_id _kind _name _value _attrs` · `_doc _block` · `_blocks _subsections _children` | an `attrs` key (`checked`, `first_ordinal`, …) |
  | links | `_id _path _doc_id _block_id _via_id _dst_id _dst_path _uri _field _dst_kind _predicate _provenance _anchor` · `_doc _dst _block` · — | none (closed) |
  | revisions | `_id _path _rev _seq _doc_id _commit _ts _origin _actor _reason _hash _is_current _archived` · `_doc` · — | none (closed) |
  | root | `_id` (`^_id`, `0^_id`) · — · the five collections | — |

  `_data.<k>` ≡ `<k>` (the merged authored view; `entries(_data)`), `_frontmatter.<k>` / `_inline.<k>` one source each — and the one way to an authored key that itself begins with `_`. `_tags` = authored `tags` ∪ body `#hashtags`; bare `tags` = the authored key alone. `_title` = the computed title; bare `title` = the authored key. Inside `follow` `$depth`/`$ordinal`/`$stop` are OQX's; a block's own nesting is `_depth`, its sibling position `_ordinal`. The hit envelope is `{ _id, _path, …projection }` (`bare: true` drops it, as today); a row rendered as a value is `{ _id, _path }`; `select _id, _path` collapses onto the envelope and an alias `_id:`/`_path:` on anything else is refused. **Unknown names (§1.5)** are one tier: a bare name no object of the kind carries is a property read that yields absent — `hints` on a read ("no document in this repository carries a property `x`; did you mean `_title`?" — the nearest match drawn from the authored keys and the engine names, so a bare `title`/`id`/`path`/`tags`/`format` is pointed at its `_` spelling), a refusal in a write selector; a bare name on `links` or `revisions` (closed: no authored data reaches them) is `filter_invalid`; a `_x` that is no engine name of the kind is `filter_invalid` naming the kind's engine names (the closed set — the one place a loud error is right). The `data.<k>` suggestions and the engine-attribute confusion tiers are gone.

## [2.2.14] - 2026-10-17

### Patch
- Dependency pins moved: omgbase-store 15.0.3 → 16.0.0, omgbase-reconcile 2.3.1 → 2.3.2, omgbase-format 0.2.2 → 0.2.3.

### Notes
- Delta tree nodes (spec/store 16.0, §4.1 "Delta nodes", §4.4 "Checkpoints"). A revision's body root, a container's children and its frontmatter may be stored as a **delta against the same list of the document's previous revision** (`seq − 1`, the base implicit) — `tree_nodes.entries` `{"d":[["=",n],["~",<entry>],["+",<entry>],["-"]]}` and a frontmatter blob `{"f":[["=",n],["~","<line>"],…]}`, told apart from the 15.x full forms by the first byte (`[`/`-` vs `{`), the ops Myers' shortest edit script grouped (the same algorithm `docs_diff_unified` pins). A revision is a **checkpoint** (every list full and self-contained, the frontmatter raw) at `(seq − 1) % 16 == 0`, when it has no live predecessor, and per list whenever the delta would not be strictly smaller. A reader resolves a `{`-form by walking back at most 15 revisions; the GC mark is explicit (a node marks what it names; the base revision marks the rest) under the **base-liveness** rule — the retention squash re-writes a kept revision in checkpoint form before archiving its predecessor (`squashed.checkpointed`), and archive segments hold checkpoint forms only. **Migration 16 is empty**: every 15.x node and raw frontmatter blob already is a checkpoint form, so the step only moves `user_version` — a major because a 15.x engine cannot read a `{`-form node. Measured (`core/store/delta.test.ts`, spec §10): a six-key frontmatter edit 44–63 B per revision against 99–103 B monolithic (blob references instead of inlined lines: 107–126 B — not chosen); a 40-block journal logline 379 B of nodes against 6.8–7.2 KB; a six-key YAML file edit 145–154 B against 738 B; twenty edits of a ten-paragraph document 5.5 KB of nodes against 38 KB; a 15-delta reconstruct 0.5 ms. Rust twin (`crates/omgbase-store`): `edit_script.rs` (the Myers script, now the store's — `omgbase-surface`'s `history.rs` re-exports it, patch), `delta.rs` (encodings, parsers, `TreeResolver`, `checkpoint_form`), `writers.rs` (`TreeWriteContext`, `write_block_tree_in`, `write_frontmatter_blob`, `previous_revision`), `observe.rs` step 0, `read.rs`/`mutate.rs` resolved frontmatter, `derived.rs`/`retention.rs` explicit mark, `archive.rs` (`checkpoint_bodies`, segments in checkpoint form, `checkpoint_dependents`, `SquashResult.checkpointed`), `schema.rs` 16; the `omgbase` CLI's `history export --json` carries `checkpointed`.

## [2.2.9] - 2026-10-14

### Patch
- Dependency pins moved: omgbase-store 14.1.1 → 14.2.0.

### Notes
- `same` dispositions are no longer persisted (spec/store 14.2, spec/cli 4.5). The matcher still produces a `same` verdict for every untouched block — and the observe outcome still counts it — but the store writes `dispositions`/`block_changes` rows only for verdicts that changed a block (`inserted`, `edited`, `moved`, `edited_moved`, `deleted`, the split/merge/copy lineage, `resurrected`, `bulk_rewrite`, the cross-document kinds). Measured on a real repository, nine in ten of the ~18.5 rows written per revision were `same`: 11 MB of dispositions plus an estimated 5–7 MB of block changes nothing read. Consequences, chosen on purpose: a block's `updated_at` (both readers: the OQX `blocks` binding and the legacy filter compiler) is now the block's own last change — inserted, edited, moved, split/merge lineage — not its siblings'; `blocks_history` lists the commits that changed the block (its tool description says so); `changes_since` summaries over api commits no longer inflate `<n> edited` with untouched blocks. The api path (`mutate/known-ids.ts`) classifies every carried block against its live row exactly as `spec/reconcile` §2 classifies a carry — raw hash, parent, sibling index — so a one-paragraph `plan`/`execute`/`blocks_update` edit writes one row instead of stamping every carried block `edited`, and a position-only change is `moved`. The first revision's `inserted` rows are untouched (the mint oracle depends on them). What is lost: the tables can no longer say "present and unchanged in commit X" — derivable by diffing two revisions (`docs_diff`). A pre-14.2 database keeps its historical `same` rows until `omg gc` runs: the default sweep now deletes them from both tables and reports `sameDispositionsSwept` (stderr `swept <b> blobs, <t> tree nodes, <s> same dispositions`; `--dry-run` counts and deletes nothing — through 4.4 it ran the empty mark-and-sweep for real), and `doctor --size` carries `same_dispositions` with an advice line past 25 % of the table. Not a migration (no `user_version` for a data-only change; opening a database never bulk-deletes). Fixtures: every store/mutate/sync/surface/cli case that projected dispositions lost exactly its `same` rows (store 694 → 552 rows over the two tables; mutate 1235 → 894, 81 api carries reclassified `moved`/`edited_moved`); new store step kinds `gc` and `exec`; new cases `identity::edit-one-of-three-writes-one-row`, `identity::move-only-change-writes-moved-rows`, `garbage::sweep-removes-pre-14.2-same-rows`, `commit::api-edit-one-of-three-leaves-siblings-same`, `commit::api-move-only-writes-moved-rows`, `reads::sibling-updated-at-does-not-move`.

## [1.3.3] - 2026-10-10

### Patch
- **Paths on the surface are `/`-rooted** (`spec/surface` 2.0, `spec/cli` 2.0; Brendan's decision of 2026-10-10). omgbase has two path forms — storage (`docs.path`, the adapters, every store/sync spec) uses git's repo-relative form (`projects/oqx.md`), while every reference an author writes is root-absolute (`/projects/oqx.md`). The surface now speaks the reference form: every path a query, an MCP tool or an `omg` verb **returns** is rooted — `$path`/`$dst_path`, every hit's `path`, rows rendered as `{ id, path }`, `docs_list`/`docs_tree` (the tree's `prefix` is `/` for the root), `docs_read`/`docs_read_at`/`docs_get_many`/`read_ref`, `docs_history`, `diff_unified`, `changes_since` (revisions, deletions, moves and the `summary`), `links_stale`/`links_repair`/`links_retarget`, `text_search`, `resolve` locators, `graph`, `docs_create`/`docs_move`/`docs_delete`/`docs_set_meta` (incl. `dangling[].path` and the dry-run `diffs` keys), `apply`, `docs_update`/`docs_plan_update` opsets, `observe*`, and the CLI's `ls`/`query`/`outline`/`show`/`new`/`mv`/`rm --doc`/`meta`/`log`/`find`/`sync`/`retarget` renderings — and every path they **accept** tolerates both forms (a missing leading `/` is added, an extra one stripped). A string literal compared with `$path`/`$dst_path` by `==`/`!=`, or passed to their `startsWith`, is rooted before evaluation, so `$path == "a.md"` keeps matching; nothing else is rewritten (a property's value is the author's: `where ^$path in list(after)` replaces `"/" + ^$path`). The keyset cursor carries the rooted path; a cursor from a 1.x surface is refused as `filter_invalid` naming the cause. Storage is unchanged — no migration.

  Both engines: one normalization module each (`packages/core/src/core/paths.ts` + `surface-paths.ts` for the other-spec result shapes; `omgbase_surface::paths`), the SQL translator renders `$path` as `'/' || d.path` with an indexed fast path for a rooted equality literal, the store-index probes de-root their value, and the conformance suites, the surface fixtures (new `path-*`, `dst-path-*`, `refs-both-forms-resolve`, `reverse-reference-by-path-membership`, `cursor-from-1x-rejected` cases, `reads::alchemy` steps) and the interop suite prove the two agree byte for byte. `@omgbase/sync` / `omgbase-sync`: the coordinator de-roots the engine's paths before handing them to a source (`sync_out`, the reconcile summary). Rust `omgbase-sync` is otherwise untouched; `spec/sync` does not move.

  **Migration:** add the slash — `$path.startsWith("projects/")` → `"/projects/"`, `$path.matches("^texts/")` → `"^/texts/"`, `"/" + ^$path` → `^$path`; a `links_stale` `target` is now paste-ready as a repair `from`; a client parsing `docs_tree`'s `prefix` reads `/` for the root; discard stored cursors (`query`, `docs_list`, `docs_tree`) and start the page sequence again.
