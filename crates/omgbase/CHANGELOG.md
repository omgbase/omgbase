## [0.27.2] - 2026-10-22

### Patch
- **OQX 0.26 — collection-scoped queries** (`spec/oqx` 0.25 → 0.26; new suite `collection-scoped`, 28 cases: 1498 → 1526 fixtures). A query names its source as the collection before its body — `modules { select id, name where id == "launch" follow distinct ^modules { where id in ^needs depth 2 } order by $depth, name }` — instead of a `from` clause inside it. The form is the 0.17 receiver block with the implicit `collect`, so it parses to the identical tree and nothing in evaluation, planning, scoping or the AST changed; what moved is what is canonical. GRAMMAR §2 now leads with `<collection> [<consumer>] [distinct] { body }`; a body never names its source (the receiver supplied the rows), so `from E` inside a body keeps its one meaning, the re-projection (`people count { from jobs where !end }`, `follow _out_links { from _dst }`); the clause form `select … from S …` stays an accepted legacy spelling of the same tree and is no longer written anywhere. **The canonical printer** (AST.md §6) writes every query whose source can head a block collection-scoped and `collect` as the bare brace (`x collect { … }` → `x { … }`, `x collect distinct { … }` → `x distinct { … }`, the projection leading without `select`; a `collect` over a directive receiver keeps the word, `jobs first { offset 0 } collect { … }`; a literal, range, operator or aggregate source still prints in the clause form) — so `references` steps print `follow kids { … }`. The source hints were reworded (`a query must name its source before its body: \`<collection> { … }\` …`; the top-level predicate error points at `<collection> { <predicate> }`). Two more sugars desugar in the parser (suite `directive-sugar`, 28 cases): **a consumer word with no block is the directive over the empty block** — `people count`, `jobs first.employer`, `_nodes exists`, `jobs count distinct >= 1`, `follow kids first` — since a consumer word right after a complete receiver can be nothing else (the printer writes the braceless form whenever the word is written and the block is empty; the clause form's top-level `from people count` keeps its whole-query hint); and **a projection-only block over a lookup is the lookup's projection** — `jobs[0] { name }` ≡ `jobs first { name offset 0 }`, `jobs[p] { name }` ≡ `jobs first { name where p }` — refused when the outer block carries a clause of its own (it runs after the pick), when the inner directive is `distinct`, or when an outer alias would shadow a name the inner `where` reads; one consequence: `jobs[0] { name }` over no jobs is now `null` (`first` of none) where the two-directive tree gave `[]`. And **`follow` is legal in every body**: a where-position directive's block yields its walk's occurrences for the consumer to reduce (`children count { follow children } > 2`, `children { ^desc: id follow children }`; `exists`/`none` over a walk are the seeds' existence) — through 0.25 it was the eval error `` `follow` is only valid on a select-position collect ``; both engines route every consumer through one row path, so the walk, `flatten`, `group by`, ordering, `distinct` and the bound apply alike. `LANGUAGE_VERSION` 0.26 in both implementations and in `@omgbase/oqx-syntax` (assets regenerated; no lexical change — `from` stays reserved).

  - omgbase surface (patch, both engines): the `query_syntax` card and manual teach the collection-scoped form (byte-identical in TS and Rust), the tool descriptions' examples and the `omg query` help examples are respelled, the `graph` macro's `queries` text prints collection-scoped (`docs { … follow distinct _out_links { from _dst depth 2 } }`), the selector's root error reads `` `docs { … }`, `blocks { … }` or `nodes { … }` ``, the selector's expression wrapper is `docs { select __omg_x: <e> }` (a malformed slot now reports `unexpected '}'` where the leaked `from` was); `spec/surface` fixtures regenerated (`reads`, `examples`, `interop`, `tool-descriptions`), `spec/cli` `invoke` regenerated. `@omgbase/dataview` emits `<source> { select … }`. Documentation, READMEs and every example converted.

## [0.27.0] - 2026-10-21

### Minor
- Surface 5.1 — the payload diet, decided from the 2026-10-21 agent-bench run (348-document repository; three payloads replayed as cached prefix on every turn):

  - `docs_tree` rolls up to directories by default: one row per directory within `depth` segments — `{ _path, docs, blocks }` — plus `files_here` (the documents at the prefix itself, counted, not listed) and `total`; `files: true` lists the documents within `depth` as lean `{ _id, _path, blocks }` rows, `updated: true` adds `_updated_at`. No `kind`, no `docs: 1`. On the timeline corpus `docs_tree { depth: 2 }` went from 26.9 kB (200 rows, a second page) to 0.9 kB (15 directory rows). The 5.0 page is not reproducible exactly (a result-shape change kept a minor: payload wins).
  - `execute { plan_id }` alone: the MCP server remembers the plans it produced in this process (the last 64 `plan` results, by id) and runs the remembered Plan through the full plan form — `stale_plan` vs `plan_mismatch` exactly as if the Plan had been echoed, a selector plan replayed without OQX — so a client sends 64 hex instead of echoing 5–19 kB. An id the server does not remember is the new `plan_unknown { plan_id }` (retriable). The plan and digest forms are unchanged; the `plan` ladder now ends "Commit: execute { plan_id }."
  - `query_syntax {}` serves a ~3.5 kB hand-written card `{ syntax, sections }`; `{ section: "<name>" }` one chapter of the manual (`sugar`, `paths`, `targets`, `scoping`, `scalars`, `predicates`, `nested`, `select`, `flatten`, `order`, `follow`, `semantic`, `examples`); `{ section: "all" }` the whole 38 kB manual 5.0 returned by default; an unknown name is `filter_invalid` with the names and a `fix`. Both engines serve every text byte for byte.

## [0.26.1] - 2026-10-20

### Patch
- **Builds on Rust 1.88+ again, and says so.** `omgbase-surface` 5.0.0 did not compile on Rust 1.92 (`error[E0658]: if let guards are experimental`, `query.rs` — the static root-name check in the surface runner used an `if let` MATCH GUARD, which only a newer rustc accepts); the arm is rewritten with the `if let` inside the arm body (equivalent: the arm fell through to `_` either way). The workspace's declared `rust-version` moves from 1.85 to **1.88** — the toolchain that stabilized `if … && let …` chains, which the crates have used since store 16 — so an older toolchain is refused with cargo's clear message instead of a mid-build syntax error. Because clippy reads `rust-version` as its MSRV, the honest value also made `collapsible_if` ask for the let-chain form wherever a nested `if let` sat inside an `if`; `cargo clippy --fix` collapsed them across the workspace (51 files, every crate named above; re-indentation only, no behavior change — the diff is clippy's own rewrite). Verified: `cargo +1.92.0 check --workspace --all-targets --all-features` compiles, `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -D warnings` clean on 1.97, and the full `cargo test --workspace` sweep.

## [0.26.0] - 2026-10-20

### Minor
- **Surface 5.0 / mutate 4.0 / sync 3.0 / search 3.0 / graph 2.0 / CLI 5.0 — "underscore = engine": on every record kind a BARE name is a user-authored entry and an UNDERSCORE-prefixed name is engine-provided, however derived.** The `_` prefix declares an engine field on a record; the bare namespace is the user's on every record — docs, blocks, nodes, links, revisions and the root row alike, because any record may carry user data later. `$` stays OQX's (`$it $key $depth $stop $leaf $frontier $ordinal`); omgbase adds no `$` names. Collections stay bare (`from docs`, `^docs`, `0^docs`, `docs count { … }`, `entries(^$it)` yields `docs blocks nodes links revisions`) — `from` names a collection, not a row property — and so do the row functions in call position (`text("x")`, `semantic(…)`, `under(…)`, `refs(x)`, …): a call is never an entry read. The self aliases are gone (`doc` on a document, `block` on a block, `section` on a node): `$it` is the self; a bare `doc` is now an authored key like any other. **Arguments and effect targets that address an engine field spell it with the underscore, and there is no tolerance**: a bare `id`/`path`/`ids` argument is an argument error whose message names the `_` spelling and whose `data.fix` is the corrected call. The Rust twin (`omgbase-surface`, `omgbase-mutate`, `omgbase-sync`, `omgbase-search`, `omgbase-graph`, the `omgbase` binary) follows in a separate round: until it lands the Rust spec runners and the cross-engine interop suite (`spec/surface` §7, `interop.json`) are red by design.

  **The language (spec/surface §1.2).** Row names, 4.11 → 5.0:

  | kind | engine names (attributes · handles · relations), 5.0 | bare names |
  | --- | --- | --- |
  | docs | `_id _path _raw _hash _updated_at _created_at _title _tags _format` · `_data _frontmatter _inline` · `_blocks _nodes _out_links _in_links _revisions` | every authored property (frontmatter + inline by the property rule): `title`, `tags`, `id`, `path`, `data`, `doc`, `format` included — nothing is reserved |
  | blocks | `_id _path _doc_id _raw _hash _updated_at _created_at _type _text _attrs _depth _ordinal` · `_doc` · `_children _nodes _out_links _section` | an `attrs` key (`checked`, `level`, `lang`; `_attrs.<k>` ≡ `<k>`) |
  | nodes | `_id _path _doc_id _block_id _kind _name _value _attrs` · `_doc _block` · `_blocks _subsections _children` | an `attrs` key (`checked`, `first_ordinal`, …) |
  | links | `_id _path _doc_id _block_id _via_id _dst_id _dst_path _uri _field _dst_kind _predicate _provenance _anchor` · `_doc _dst _block` · — | none (closed) |
  | revisions | `_id _path _rev _seq _doc_id _commit _ts _origin _actor _reason _hash _is_current _archived` · `_doc` · — | none (closed) |

  `_data.<k>` ≡ `<k>` (the merged authored view; `entries(_data)`), `_frontmatter.<k>` / `_inline.<k>` one source each — and the one way to an authored key that itself begins with `_`. `_tags` = authored `tags` ∪ body `#hashtags`; bare `tags` = the authored key alone. `_title` = the computed title; bare `title` = the authored key. Inside `follow` `$depth`/`$ordinal`/`$stop` are OQX's; a block's own nesting is `_depth`, its sibling position `_ordinal`. The hit envelope is `{ _id, _path, …projection }` (`bare: true` drops it, as today); a row rendered as a value is `{ _id, _path }`; `select _id, _path` collapses onto the envelope and an alias `_id:`/`_path:` on anything else is refused. **Unknown names (§1.5)** are one tier: a bare name no object of the kind carries is a property read that yields absent — `hints` on a read ("no document in this repository carries a property `x`; did you mean `_title`?" — the nearest match drawn from the authored keys and the engine names, so a bare `title`/`id`/`path`/`tags`/`format` is pointed at its `_` spelling), a refusal in a write selector; a bare name on `links` or `revisions` (closed: no authored data reaches them) is `filter_invalid`; a `_x` that is no engine name of the kind is `filter_invalid` naming the kind's engine names (the closed set — the one place a loud error is right). The `data.<k>` suggestions and the engine-attribute confusion tiers are gone.

Role arguments keep their names: `docs` (a list of refs), `blocks` (an op's operand list), `to`, `at`, `roots`, `select`, `expect`, `effects`, `plan`, `plan_id`, `reason`, `diffs`, `markdown`, `text`, `content`, `frontmatter`, `set`, `unset`, `section`, `checked`, `separator`, `prop`, `value`, `resolution`, `depth`, `limit`, `cursor`, `budget_tokens`, `include_ids`, `include_deleted`, `at` (a revision), `rev`, `from_rev`, `to_rev`, `path_glob`, `docs_tree.path` (a prefix), `docs_create.path` and `to_path` (where to create / move — no row carries the path yet), `observe*.path` / `files[].path` (a file event's path), `from_target`, `to_target`, `repairs`, `q`, `query`, `bare`, `origin`, `degrees`, `direction`, `predicate`, `max_documents`, `summary`, `repo`. **No tolerance**: `{ id }`, `{ path }`, `{ ids }` are `filter_invalid { hint: "arguments", fix }` — "`id` is not an argument — the document's id is `_id` (an engine field: the bare namespace is the user's)", the `fix` the same call respelled; `doc`/`block`/`node` keep their retired-name messages, now pointing at `_id`/`_path`.

  **Effects (spec/mutate 4.0, §11).** Targets `{ kind: "document", _id? | _path? }`, `{ kind: "block", _id }`, `{ kind: "node", _id }` (`{ kind: "section", heading_id }` and the bare forms — a path, a `b_`/`d_`/`n_` id, `$new.n` — are unchanged); fields `_frontmatter.<key>` (set/unset) and `_attrs.checked` (a block's checkbox) beside the role names `content` and `markdown`; a node's field stays its editor's property name (`value`, `name`, `checked`); `expect.content_hash` / `parent_children_hash` / `revision` are roles. A selector's `row` origin and a `-> ` expression's row ref are `{ _id, _path }`. The sugar builders, the fixtures and every `fix` follow.

Schema 14 adds `pending_materializations` (one row per path: write / rename / remove, the revision, the hash the file must have, the commit) with migration 13 → 14; an older engine refuses a 14 database as before. An observation of a pending path treats bytes hashing to the recorded hash as an echo, a missing file as not-yet-written (no tombstone), and anything else as a human edit that wins (ADR-004). `docs_delete` unlinks only a file whose bytes still match; `docs_move` falls back to writing the destination when the rename cannot happen. The guarantee the specs now state: all-or-nothing in the database, files eventually consistent through recorded intent, no cross-resource atomicity claimed. Fixture projections gain a `pending_materializations` key; new `crash_after_commit` and `materialize` observation steps. `omg sync` / `omgbase sync` JSON gains `materialized: [path…]` (the files the sweep's step 0 wrote; `spec/cli` 3.1, an additive key).
