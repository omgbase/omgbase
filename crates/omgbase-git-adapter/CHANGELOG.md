## [0.2.0] - 2026-10-27

### Minor
- Modular-core Phase 6a, the Rust twin — **the Git-backed history provider** (spec/store 17.5 §5.12, spec/surface 6.4, spec/cli 5.5, spec/sync 4.5), mirroring the TypeScript reference file by file. `omgbase-store`: the `HistoryReader` seam split out of `HistoryRecorder` (the read half — `read_at_revision`, `blocks_history`, `diff_blocks`, `diff_unified`, `latest_revisions`, `doc_versions`, `revision_rows`, `doc_revision_rows`, `has_revision`, `uncaptured_heads`, `disposition_counts`; the native `blocks_history`/`docs_diff`/`docs_diff_unified`/`docs_history` rows moved behind it from the surface), the `HistoryProvider` seam (`name`, `available`, `reader`, `enable`, `purge`, `checkpoint`) and `Capabilities::providers` / `with_provider`, the fifth `Composition::Git` (`has_git_provider`), provider-aware manifest reads (`history_provider_of`, `history_reader_for`/`_for_doc`/`_if_available`, `require_provider` → the `history_provider_unavailable` alert, `capture_for` None on a provider row, `any_history_enabled` native-only, `require_writer` by the row's provider), `enable_history` with a provider and its options, the provider conflict (`Error::HistoryProviderConflict`), `purge_history` → the provider's purge, `history_checkpoint`, the `unsupported` read state (`Error::HistoryUnsupported`) and `Error::HistoryProviderUnavailable` with the pinned messages, the sixth fault site `git.commit` (+ `set_armed_fault`, an in-process arm for runners), `unified_diff` in `history::diff`. NEW crate **`omgbase-git-adapter`**: the plumbing wrapper (every spawn under `GIT_DIR`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_ATTR_NOSYSTEM=1`, no `HOME`, `LC_ALL=C`, `TZ=UTC`; the committer identity, raw `@<unix> +0000` dates; `OMGBASE_GIT_BIN`), the trailer codec, the checkpoint worker (resume from the tip's `omgbase-seq`, the `$git` cursor row, `changes_since` paging, blobs from `reconstruct`, a temp index, `commit-tree -F -`, the fault point, `update-ref` CAS, the rescan), the `GitHistoryReader` (the native shape with `_commit` the git sha and `_hash` the blob's sha256, the sha decision table). `omgbase-sync`: `version.capabilities.history` gains `provider` and `completeness`, `history_state` by the row's provider, the sweep's step 6 `run_provider_checkpoint`. `omgbase-surface`: the history tools dispatch through the repository's reader, the two new error envelopes. `omgbase`: attaches the provider before any store opens (the fixture identity under the conformance seams), `history enable --provider git [--branch] [--cadence]`, `history checkpoint`, `history purge` on a git repository, `doctor`'s provider line. The runners mirror the five-composition rules; the commit shas the fixtures pin are reproduced byte for byte.
- Modular-core Phase 6b, the Rust twin — **the remote half of the Git-backed history provider** (spec/store 17.6 §5.12, spec/surface 6.5, spec/cli 5.6, spec/sync 4.6), mirroring the TypeScript reference file by file. `omgbase-store`: the `HistoryVaultSink` seam (the vault as the remote half writes inbound content into it — a batch of `VaultChange`s applied as external edits through the observe path; the Rust seam also lends the connection, since a sink owns the store for the call), `remote_summary`/`remote_sync` on `HistoryProvider` (default `None`), `CheckpointResult.push` (`PushOutcome`: the receipt or `{ error }`), `PushResult`, `RemoteState`/`RemoteSummary`, `RemoteSyncResult`, `update_history_provider_config` (the row's `config` rewritten in place — state, coverage, versions and `writer_requires` untouched), providers held as shared handles (`Store::provider_handle`, `require_provider_handle`), the error codes `git_remote_diverged` and `git_merge_conflict` with the alerts' messages. `omgbase-git-adapter`: the remote binding `{ name, url, branch, push: off | on-checkpoint | periodic, fetch: off | periodic | webhook }` (`remote_config_for`, credentials refused), `GitRepo`'s remote plumbing with the reference's argv (`push --porcelain --quiet`, `fetch --quiet --no-tags`, `ls-remote`, `merge-base [--is-ancestor]`, `diff-tree -r -z --no-renames`, `ls-tree -r -z`, `rev-list --reverse`, multi-parent `commit-tree`), the `remote` module — `remote_set|unset|status`, `push_branch` (never `--force`; a rejection raises `git_remote_diverged`), `fetch_remote` (fast-forward through the sink; the tree-level three-way merge with one merge commit carrying `omgbase-merge`; conflicts kept as `<stem>.remote-<short>.md` sidecars under `git_merge_conflict`), `resolve_conflict`, the rewritten remote detected-stopped-alerted with push and fetch paused, `reconcile_remote` (`--rebase` replaying the unpushed commits byte for byte with the ids ref rebased alongside, `--merge`, `--adopt` with `<stem>.local-<short>.md` sidecars, `--fork`), `remote_sync` for the sweep and `push_after_checkpoint` — the ref names, alert codes, detail keys and messages byte for byte; the `ids` module (`refs/omgbase/ids`: one canonical-JSON id map per live document, a parallel chain with `omgbase-seq` and `omgbase-content`); the worker's no-op rule (a tree equal to its parent's writes no commit; the `$git` row advances) and resume rule (the row refines the tip's trailer when it names the same tip); the `$git` row's `pushed`; the `scheduler` (`every` synchronous in the mutation hook, a debounce timer coalescing a burst, `flush` at shutdown). `omgbase-sync`: the sweep's steps 7–8 (`run_provider_remote_sync` over `FsVaultSink` — files under the root as external edits, then `process_checkpoint` and the stat cache), `version.capabilities.history.remote`. `omgbase-surface`: the two error envelopes. `omgbase`: `history remote set|unset|status|resolve|reconcile`, `history push`, `history fetch`, `checkpoint`'s push line, the help card, the MCP host's checkpoint scheduler (notified by the catalog's mutation hook and the watcher's checkpoints). The store, surface and CLI runners gain the remote devices (`git_remote*`, `git_push`, `git_fetch`, `git_resolve`, `git_reconcile`, `git_remote_commit` under the identity `remote <remote@fixture>`, `git_remote_log|tree`, `git_ids_log|show`, `alerts`; the CLI step key `remote`); every pinned sha of the new fixtures is reproduced byte for byte.
