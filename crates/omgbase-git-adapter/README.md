# omgbase-git-adapter

The **Git-backed history provider** for [omgbase](https://github.com/omgbase/omgbase), Rust implementation — the twin of `@omgbase/git-adapter` (modular-core Phase 6a the engine-owned repository, 6b the remote half; `spec/store` §5.12, `spec/surface` §3 "The git provider", `spec/cli` `history`, `spec/sync` §4.3/§6). A repository's history is kept by **one provider**: the engine's native recorder (the store's own history tables) or this one — a **bare Git repository at `<workspace>/.omgbase/git`** whose commits are built from the database rows by a **checkpoint worker** consuming the change feed, and which may be bound to a **remote** the engine pushes to and fetches from. The core (`omgbase-store`) knows the provider only by name: the composition layer (the `omgbase` binary, the fixture runners) attaches it before a store opens:

```rust
use omgbase_git_adapter::{GitHistoryProvider, default_identity};
use omgbase_store::Capabilities;

let caps = Capabilities::standard().with_provider(Box::new(GitHistoryProvider::new(workspace_root, default_identity())));
```

## What it does

- `omg history enable --provider git [--branch <b>] [--cadence every|<ms>]` — `git init --bare`, the `.omgbase/` line in the user's `.git/info/exclude`, the manifest row `{ provider: "git", git_dir: ".omgbase/git", branch, cadence, ids_ref: "refs/omgbase/ids", remote: null }`, one **baseline** commit of the full current tree.
- **The checkpoint worker** (`omg history checkpoint`; the freshness sweep's step 6; the MCP host's mutation hook through the `scheduler` — `every` synchronously after each write, a debounce timer coalescing a burst): resumes by the **resume rule** (the branch tip's `omgbase-seq` trailer, refined by the `$git` row of `sync_state` when it names the same tip and stands further on), pages `changes_since`, stages each row's documents from the ROWS (`reconstruct` → `git hash-object -w --stdin`; a move = remove + add; a delete leaves the tree), builds the tree through a temporary index, `commit-tree` with the replay trailers, the `git.commit` fault site, `update-ref` by compare-and-swap; the **no-op rule**: a tree equal to its parent's writes no commit and the row alone advances. Cadence `every` is one commit per feed row; `{ debounce_ms }` folds the pending rows into one. Beside every checkpoint the **ids ref** `refs/omgbase/ids` gains one commit: a canonical-JSON id map per touched document at `.omgbase/ids/<doc_id>`, trailers `omgbase-seq` and `omgbase-content: <content sha>`.
- **Trailers**: `omgbase-seq`, `omgbase-ts`, `omgbase-commit` (one per row), `omgbase-origin`, `omgbase-actor`, `omgbase-plan`, `omgbase-rescan` (a snapshot), `omgbase-merge: <remote tip>` (a merge commit), `omgbase-content: <sha>` (the ids ref), `omgbase-doc: <doc_id> <path> <head|->` — rendered and parsed by the engine, never by `git interpret-trailers`.
- **The remote half** (`remote`): `omg history remote set --url <url> [--name] [--branch] [--push off|on-checkpoint|periodic] [--fetch off|periodic|webhook]` writes the binding into the row (`update_history_provider_config`) and `git remote add|set-url`; `omg history push` pushes the branch and the ids ref — **never `--force`**; a rejected push raises `git_remote_diverged` (a fetch merges, the push lands after). `omg history fetch` fast-forwards through the **vault sink** (`HistoryVaultSink`: inbound content enters as external edits — the `omgbase` binary's `FsVaultSink` writes files under the root and runs the observe path, the fixture runners `observe_batch`), or runs a **three-way merge at the tree level** with `git merge-base` when both sides moved — one merge commit with `omgbase-merge`; conflicts keep both versions, the remote's as `<stem>.remote-<short>.md`, under the `git_merge_conflict` alert until `omg history remote resolve <path> --ours|--theirs`. A **rewritten remote** (its tip no longer descends from the tip we last knew) is detected, stopped and alerted (`git_remote_diverged` with `old_remote_tip`; the old tip on `refs/omgbase/diverged/<name>`; push and fetch pause while checkpoints continue) until `omg history remote reconcile --rebase|--merge|--adopt|--fork` — each backing the old tip up on `refs/omgbase/backup/<ts>`, `--adopt` keeping local edits as `<stem>.local-<short>.md`, `--fork` pushing the branch as `<branch>-omgbase-<ts>` under `git_remote_forked`. The sweep's steps 7–8 run push/fetch under the `periodic` policies; `version.capabilities.history.remote` reports `{ name, branch, state, pushed_through }`.
- **Reads** through the `HistoryReader` seam: `docs_history` (`_commit` the git sha, `_hash` the blob's sha256, `_rev` the trailer's head token), `docs_read { at: <sha> | <head> }`, `docs_diff_unified`, the `revisions` root; the current head unretained until a commit names it; a sha is decided here (`pruned`, `outside_coverage`, `target_missing`); `blocks_history` / `docs_diff` are `unsupported`.
- **Determinism**: every spawn runs `git` with `GIT_DIR`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_ATTR_NOSYSTEM=1`, no `HOME`, `LC_ALL=C`, `TZ=UTC`; the committer `omgbase <omgbase@localhost>` (`omgbase@fixture` under the conformance seams), the author's name the row's actor, both dates the row's `ts` as `@<seconds> +0000` — so the shas the fixtures pin are the same in both engines. `OMGBASE_GIT_BIN` names the executable (default `git`).

Unavailability is loud and writes continue: without `git` on PATH every history read of a git-provider repository is `capability_unavailable { history, unavailable, provider, reason }` and the `history_provider_unavailable` alert is raised; the next checkpoint that runs catches up. Credentials never enter omgbase: a URL carrying a user or password is refused; `git` resolves access through the host. Restoration of identities from a clone's `refs/omgbase/ids` is 6c.
