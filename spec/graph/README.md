# The omgbase graph specification

The graph layer projects **semantic nodes** out of a document's blocks
(links, wikilinks, tasks, anchors, inline fields, sections) and extracts the
**authored edges** between documents (links, frontmatter relations, inline
relations), resolves their targets to node ids, keeps the **open** edge set
current across commits (3.0: `edges` holds the asserted relations only — the
interval record of when an edge opened and closed is the recorder's
`edge_transitions`, `spec/store` §3.1), and rolls them up per document.
Everything here is **derived from content, never inherited through
identity**: extraction is a pure function of a revision's blocks and
frontmatter, recomputed at every commit; block identity only threads the
edge keys. This directory specifies
that projection so more than one engine writes the same `nodes`,
`external_nodes`, `edges` and `doc_edges` rows into the shared database
(`spec/store`). It is owned by neither implementation.

| Implementation | Where | Role |
| --- | --- | --- |
| `@omgbase/core` (TypeScript, npm) | `packages/core/src/graph/extract.ts`, `format/markdown.ts` (`projectNodes`), `core/store/{nodes,edges}.ts`, the resolution in `sync/reconciling-ingest.ts`, `core/ingest.ts` | **Reference.** Graph decisions land here first. |
| `omgbase-graph` (Rust, crates.io) | `crates/omgbase-graph` | Conformance-first port: the pure extraction and projection; `omgbase-store` resolves and writes. The 3.0 twin follows the TypeScript reference in its own round. |

The spec is two artifacts, versioned together by `VERSION`: this `README.md`
and `cases/*.json`. **When prose and fixtures disagree, the fixtures win**,
and the prose gets fixed. Design rationale: `docs/graph-and-query.md` §1–§2.

## Versioning

`VERSION` is `<major>.<minor>`; the `omgbase-graph` crate is
`<major>.<minor>.<patch>`. A change to *which* nodes or edges a document
yields (a scanner, a normalization, a resolution rule) bumps the minor; a
change to a row's meaning (`node_id`, `edge` columns, the rollup) bumps the
major. The reference's `EXTRACTION_VERSION` (`x2`) is folded into this
version: it is not persisted anywhere, and a document picks up a newer
extraction the next time it is ingested.

## The rule for changing the graph

**Fixture first, TypeScript (reference) second, Rust third.** Inputs are
observation scripts (as `spec/store` §9.4); each case's `expect` is
generated by the reference (§7). Divergences are adjudicated by this prose;
§8 records the reference oddities surfaced and the decisions taken.

## 1. Inputs

A committed document as `spec/store` §5.4 has it inside the commit
transaction: the body blocks with their ids, the `frontmatter` mapping as
`spec/properties` §3.1/§4 parses it (`{}` when there is none or it failed),
the document's `doc_id` and `path`, and the repo's current live documents
(for target resolution). Markdown only in this version.

Block-level scanning always works on **`mask_code(own(raw))`** — the
block's `raw` with every direct child's span blanked (`own`, so a container
scans only its own text and a feature belongs to the innermost block that
contains it — since 1.1, §8) and then fenced code and inline code spans
blanked (`spec/properties` §3.2 defines both; both are length-preserving so
spans still index the original `raw`) — and skips `code_fence` blocks
entirely. Code is not prose.

## 2. Nodes

### 2.1 Projection (Markdown adapter)

Walk the body blocks in pre-order; for each block *b* (id `B`), over `scan =
mask_code(own(b.raw))` (empty for `code_fence`), in this order, all matches:

| Kind | Pattern over `scan` | `name` | `value` | `attrs` | span |
| --- | --- | --- | --- | --- | --- |
| `md:link` | `\[([^\]]*)\]\(([^)\s]+)(?:\s+"[^"]*")?\)` | link text | destination | `{}` | the match |
| `md:wikilink` | `\[\[([^\]]+)\]\]` | — | the inner text (alias included: `note|alias`) | `{}` | the match |
| `md:task` | *b* is a `task` block | — | `b.text` (visible text) | `{ "checked": bool }` | `[0, len(raw))` |
| `md:anchor` | `\^([a-zA-Z0-9_-]+)` | the ref | — | `{}` | the match |
| `md:inline_field` | the bracketed form, then the line form, exactly as `spec/properties` §3.2 | key as written | value trimmed | `{}` | bracketed: the match; line form: from the key to the end of the trimmed value |

`![alt](x)` matches `md:link` (the `!` is outside the pattern). A container's
own text excludes its children, so a feature inside a list item is projected
once, for the item (before 1.1 also for the list — §8). `md:inline_field` nodes are projected
**and** the same occurrences become `properties` rows (`spec/properties`).

### 2.2 Section nodes

After the adapter nodes, one `md:section` node per row of the `sections`
table (`spec/store` §4.5), in `first_ordinal` order: `block_id` = the
heading block, `name` = the heading's `text`, `value` null, `attrs = {
"level", "first_ordinal", "last_ordinal" }`, no span.

### 2.3 Node rows

A document's nodes are the adapter nodes (projection order) followed by the
section nodes. For each, with `ordinal` = the count of earlier nodes of the
same `(kind, block_id)` in this list (from 0):

```text
node_id     "n_" + first 12 hex of sha256(doc_id + "|" + block_id + "|" + kind + "|" + ordinal)
repo_id, doc_id
block_id    the block's id (always a real id at ingest)
kind, name, value
span_start  byte offset of the span start within the block's UTF-8 raw, or null
span_end    byte offset of the span end, or null
attrs       JSON object (compared as JSON)
```

Spans are **bytes** (`spec/format` §1 inv. 5); the reference computes them
as UTF-16 code units and converts at the store boundary (§8). The store
deletes the document's nodes (and their FTS rows) and reinserts on every
commit.

## 3. Edges

### 3.1 Extraction (`x2`)

An **edge descriptor** is `{ src_block, src_field, predicate, dst_kind,
target, anchor, provenance }`. A **destination** `dest` is classified:

- `^https?://` → `dst_kind = external`, `target = normalize_uri(dest)`,
  `anchor = null`;
- otherwise split off the fragment at whichever marker comes **first**: a
  `^` before any `#` makes a ref (`a^b#c` → path `a`, anchor `b#c`,
  `dst_kind = block`); otherwise a `#` makes a heading anchor (`a#b^c` →
  path `a`, anchor `b^c`, `dst_kind = document`); no marker → `anchor =
  null`, `dst_kind = document`. `target` is the path part (possibly `""`).

**Per block** *b* (skip `code_fence`), over `mask_code(own(raw))`, deduplicating
within the block on `(predicate, target, anchor, src_field)` (first wins):

1. **Inline relation fields**: `(?:^|\s)([a-z][a-z0-9_]*)::\s*(\[\[[^\]]+\]\]|\/[^\s]+|https?:\/\/[^\s]+)`,
   case-insensitive — only values that are a wikilink, a root path or a URL
   are relations (a plain `key:: text` is a property, not an edge). `key` is
   **lower-cased**; `predicate = src_field = key`; `dest` is the wikilink's
   inner text or the raw value; `provenance = inline_field`. Remember each
   raw value so the same string is not also counted by steps 2 and 3 (step 4
   does not consult it — §8).
2. **Markdown links and images**: `(!?)\[[^\]]*\]\(([^)\s]+)(?:\s+"[^"]*")?\)`;
   skip a destination remembered in step 1; `predicate = embeds` for `!`,
   else `references`; `provenance = link`.
3. **Wikilinks**: `(!?)\[\[([^\]]+)\]\]`; skip when `[[inner]]` was
   remembered in step 1; same predicates as step 2. (An alias `[[a|b]]` is
   part of the destination — §8.)
4. **Autolinks** `<(https?:\/\/[^>]+)>` and **bare URLs**
   `https?:\/\/[^\s)>\]]+` at a word boundary and **not** preceded by `(`,
   `"` or `[` (the reference uses a lookbehind; a port checks the previous
   character): `references`, external, `provenance = link`.

**Frontmatter**: for each **top-level** entry `(key, value)` of the mapping
in parser order, over the value itself or each element when it is an array:
a string that is exactly `[[…]]` yields `dest` = the inner text; a string
starting with `/` yields `dest` = the string; anything else yields nothing
(nested mappings are not walked). Descriptor: `src_block = null`,
`src_field = predicate = key` (**case preserved**), classified as above,
`provenance = frontmatter`.

Extraction order: all blocks in pre-order (each block's steps 1–4), then the
frontmatter entries.

### 3.2 Resolution

Each descriptor's target becomes a node id, in extraction order:

- `external` → the repo's `external_nodes` row for `(repo_id, uri)`, minting
  **`x`** and inserting `(node_id, repo_id, uri, title = null)` when absent.
- `target = ""` (a pure fragment `#H` / `^ref`) → the source document itself,
  `dst_kind = document`.
- otherwise: `canonical = resolve_relative(target, doc_dir)` — a `./` or
  `../` target is joined to the document's directory (`"a/b/"` for
  `a/b/c.md`, `""` at the root) and normalized segment-wise (`.` and empty
  dropped, `..` pops); any other target is taken as is — then one leading
  `/` is stripped. If a **live** doc of the repo has that path, `dst_node` =
  its `doc_id`; else `dst_node = "phantom:" + canonical`. `dst_kind` is
  forced to **`document`** even for a `^ref` (block-ref resolution is not
  attempted; the anchor is kept on the edge — §8).

### 3.3 Open-edge maintenance (per commit; 3.0)

Key = `src_block|src_field|predicate|dst_node|anchor` (nulls as empty).
Let *open* be the document's `edges` rows and *wanted* the resolved
descriptors deduplicated on key (first wins). For each wanted key not open:
**mint `e`**, insert `(edge_id, repo_id, src_doc, src_block, src_field,
predicate, dst_kind, dst_node, anchor, provenance, via_node = null)`, in
wanted order. Then for each open row in `rowid` order: keep it if its key is
wanted and no earlier open row with the same key was kept; otherwise
**delete** it. Unchanged rows are untouched (they keep their `edge_id`).
**The recorder's half (`spec/store` §5.4 step 15):** when history is enabled
the transition's edge list — the rows opened, the ids closed — lets the
recorder write `edge_transitions`: one row per opened edge (16.x's `edges`
row verbatim, `from_commit` = this commit, `to_commit = NULL`) and
`to_commit = this commit` on every row it closed; the core writes neither
column. Through 2.x the core table carried the two columns itself: a closed
edge stayed as a row with `to_commit` set, and every reader filtered
`to_commit IS NULL`. The `edges` table has no `collection` destination
(`dst_kind ∈ document | block | external`; the `collections` table left
with it — `spec/store` D9).

Mint order within a commit (`spec/store` §5.4): every `x` during resolution
(descriptor order), then every `e` during insertion.

### 3.4 Rollup (`doc_edges`)

After maintenance, delete the document's `doc_edges` and insert one row per
group of its edges (every row is open, 3.0) by `(predicate, dst_node,
dst_kind)`: `count` = the group size, `samples` = JSON array of up to three
non-null `src_block`s in edge `rowid` order. Groups are emitted in the order SQLite's `GROUP BY`
yields them (the table is compared as a set).

### 3.5 Phantom adoption

When a document row **becomes live** at a path — created new, or a
tombstoned row revived by re-creation (`spec/store` §5.4 step 2) — every
edge in the repo with `dst_node = "phantom:" + path` is rewritten in place
to `dst_node = doc_id` (the edge keeps its id; the recorder's open
`edge_transitions` row follows the rewrite, so the interval record reads as
16.x's `edges` did), and the rollup of each affected source document is
recomputed. An edge deleted before the target appeared has no row to adopt
(2.x: a closed row was not adopted). Backlinks
therefore appear the moment the target exists, and reappear when it comes
back (§8: the reference adopted on creation only). A tombstoned document's
inbound edges are **not** re-phantomed (§8).

### 3.6 Deletion

An observed deletion (`spec/store` §5.6) leaves the document's edges in
place — a tombstoned document's edges stay open — and its `nodes`,
`external_nodes` and `doc_edges` rows too (§8).

## 4. Normalizing URIs

Only destinations matching `^https?://` **case-sensitively** are external
(§3.1); `HTTPS://a.com/x` and `mailto:x@y.com` are paths and resolve to
phantoms (`uri::uppercase-scheme-is-not-external`, `uri::mailto-link-is-a-path`).
`normalize_uri(s)`: parse `s` as a WHATWG URL; on failure return `s`
unchanged. Otherwise drop the fragment, lower-case the host (WHATWG does;
the host is also IDNA-encoded: `ünïcode.example` → `xn--ncode-cta3g.example`),
drop an explicit default port (`:80` for `http`, `:443` for `https`),
serialize, and strip **one** trailing `/`. Consequences pinned by the
fixtures: `https://a.com` and `https://a.com/` both give `https://a.com`;
`https://a.com/./x/../y` gives `https://a.com/y`; a space in the path
becomes `%20`; `%2F` stays; `?` with an empty query survives
(`https://a.com/?`); `//double` in a path survives. Rust's `url` crate is a
WHATWG implementation and agrees on these; the fixtures are the contract.

## 5. Node and edge identity across engines

`node_id` is a content hash over ids already shared (§2.3), so both engines
compute it. `x` and `e` are minted (`spec/store` §2.2): the fixture minter
makes them comparable given the mint order of §3.2–§3.3. Phantom ids are
paths.

## 6. Reads this spec pins

- **Document links** (`omg links`; at the query surface `_out_links`/`_in_links`, `spec/surface` 5.0): out = the doc's
  `doc_edges` (or its `edges` rows at block grain), in = the `edges` rows
  whose `dst_node` is the doc, grouped by `(predicate, src_doc)`. Every row
  is open (3.0), so no reader filters an interval.
- **Stale links**: an edge whose `dst_node` starts with `phantom:` is
  `dangling_doc`; external edges are counted, never verified; anchors are
  not verified in this version.
- **`has_anchor()`** (`spec/surface` §1.3) probes `edges` for a row of the
  block with a non-null `anchor` — with no interval filter (D8 made the
  filter explicit in surface 5.1; 3.0 makes it moot: a link edited away has
  no row). `reads::has-anchor-open-edges` stays as the pin.

Both are projections a runner can recompute from the tables; the fixtures pin
the tables. The surface renders them (`spec/surface` §4 `links_stale`,
`docs_move`'s `dangling`, the `graph` tool, the `omg links` verb) under the
`links` kind's **engine names** of `spec/surface` §1.2 (5.0: on every record
a bare name is the user's and an underscore-prefixed name the engine's) —
`_doc_id`/`_block_id` for `src_doc`/`src_block`, `_field` for the
`src_field` column, `_dst_id` for `dst_node`, `_dst_path`, `_predicate`,
`_provenance`, `_dst_kind`, `_anchor`, `_path` for the source document's
path — so a reader of a tool result and a reader of a query (`follow
_out_links { from _dst }`) see one vocabulary; the role keys of
those results (`target`, `authored`, `reason`, `count`) stay bare. Through
4.x the same names were rendered bare (`doc_id`, `dst_id`, `path`, …). The
columns themselves (`spec/store`'s `edges` table, which these fixtures pin),
the node kinds (`md:section`, `md:link`, …) and every value in a row keep
their names: they are storage and data, not the surface's spelling.

## 7. Fixtures

`cases/<suite>.json`; observation scripts exactly as `spec/store` §9.4
(`steps` of `observe`/`sweep`, fresh database, repo `rp_0`, the fixture
minter). `expect` is the projection after the last step of:

- `nodes`: sorted by (`doc_id` in `docs` order, `node_id` bytewise) —
  `{ node_id, doc_id, block_id, kind, name, value, span_start, span_end,
  attrs }`;
- `external_nodes`: sorted by `uri` — `{ node_id, uri, title }`;
- `edges`: sorted by (the opening commit's `seq` **as the runner remembers
  it**, then `edge_id` bytewise) — every column but `repo_id`. The row no
  longer carries the commit that inserted it (3.0), so the runner remembers
  it: after every observe step, each `edges` row of a committing member's
  document not seen before was opened by that member's commit (a document
  commits once per batch; adoption keeps the id), whose `seq` the core's
  `feed` gives;
- `doc_edges`: sorted by (`src_doc` bytewise, `predicate`, `dst_node`) —
  `{ src_doc, predicate, dst_node, dst_kind, count, samples }`.

Suites: `nodes.json` (every kind, spans incl. non-ASCII, ordinal within a
block, containers, masking, section nodes), `links.json` (each scanner,
classification, anchors, images, dedup, inline-field precedence over plain
links, frontmatter relations incl. arrays and case), `resolve.json`
(relative paths, root paths, phantoms, self fragments, external minting and
reuse, `^ref` forced to document), `open-edges.json` (3.0: edges kept,
deleted and re-opened with a new id across revisions; adoption on creation
and revival; deletion leaves edges; rollup counts and samples — the 21
scripts of 2.x's `intervals.json`, projecting `edges` and `doc_edges`; the
interval record those scripts also pinned is `spec/store`'s
`history/edge-transitions.json`, the same scripts projecting
`edge_transitions`), `uri.json` (§4 table).

**Runner checks**: every `node_id` equals its §2.3 derivation; every
`edges` row's `dst_node` is a doc id (live or tombstoned — §3.6), an
`external_nodes` id, or `phantom:<path>` with no live doc at that path
(adoption §3.5 guarantees this); `doc_edges` equals the rollup recomputed
from the `edges` rows; then deep-equal to `expect`. (The check that every
`from_commit`/`to_commit` names a commit moved with the suite to
`spec/store` §9.5.)

**The four compositions** (`spec/store` §9.6; modular-core Phase 5a):
nothing in this suite reaches a history or a vector table — the interval
record left for the recorder's suite in 3.0 — so every case is compared AS
RECORDED under `OMGBASE_CAPABILITIES=core|history|semantic|full`; the runner
prints `[graph spec] composition=<name>: compared=<n> mapped=0 skipped=0` for
`pnpm conformance` and refuses `GRAPH_SPEC_UPDATE` under a reduced composition.

**Generation.** `packages/core/corpus/graph/spec.test.ts`,
`GRAPH_SPEC_UPDATE=1`. **Allowlist (Rust).**
`crates/omgbase-graph/tests/spec-passing.txt`, `GRAPH_SPEC_UPDATE=1`; the
Rust runner (`crates/omgbase-graph/tests/spec.rs`) drives `omgbase-store`
through a path-only dev-dependency (dropped at publish) since the tables are
written in the commit. The store's edge maintenance walks the open rows
`ORDER BY rowid` in both engines; a duplicate open row (which maintenance
prevents) is deleted by the next commit to the document.

## 8. Reference oddities surfaced while specifying, and decisions

- **Changed (3.0) — `edges` holds open rows only.** Through 2.x an edge was
  closed by setting `to_commit` and the row stayed; every reader filtered
  `to_commit IS NULL`, `idx_edges_temporal` indexed the interval and nothing
  read it, and the one reader without the filter (`has_anchor()`) answered
  true for a link edited away until surface 5.1 added it. The current state
  now owns only what is asserted (M6 of `docs/modular-core/`): closing an
  edge deletes its row, `from_commit`/`to_commit` and `idx_edges_temporal`
  are gone, `idx_edges_src`/`idx_edges_dst` lose their `WHERE`, and the
  interval record is the recorder's `edge_transitions` (`spec/store` §3.1,
  §5.4 step 15), written from the transition's edge list the core hands it
  and following an open edge's in-place destination rewrite. What moved in
  the fixtures: every `edges` row lost `from_commit`/`to_commit`; the one
  closed row a non-interval suite projected (`resolve::deleted-target-re-
  extraction-phantoms`) is gone; `intervals.json` moved to `spec/store/cases/
  history/edge-transitions.json` (projecting `edge_transitions`, every row as
  2.x projected it) and its scripts were re-cut here as `open-edges.json`.
  Decided in the implementation: **the recorder mirrors adoption and a
  move's re-phantoming** on the open transition row (`HistoryRecorder.
  retargetEdges`) so the moved suite's rows are byte for byte 2.x's — the
  alternative, a transition that keeps the destination as opened, would have
  made the interval record disagree with the edge it describes; **the
  recorder holds the opened edge's claim** (bit 1 — `spec/store` §2.1, H6),
  as it holds every id its rows name.
- **Fixed — a revived document adopted no phantoms.** The reference ran
  adoption only when a `docs` row was inserted, so a document deleted and
  re-created at the same path kept every inbound link dangling
  (`phantom:<path>` open while the path was live again — the §7 check would
  have failed). §3.5 now adopts whenever the row becomes live
  (`open-edges::recreated-at-tombstoned-path-adopts`).
- **Pinned — an inline relation's URL is also a bare-URL edge.** Step 1's
  remembered values shadow steps 2–3 only, so `source:: https://a.com/x`
  yields the `source` edge and a `references` edge
  (`links::inline-relation-url`); and `parent:: /p.md and [a](/p.md)` drops
  the `references` edge for the same destination
  (`links::inline-relation-shadows-md-link-with-same-destination`).
- **Pinned — autolinks are scanned twice.** `<` is not in the bare-URL
  exclusion, so `<https://a.com/x>` matches both scanners (deduplicated when
  the targets agree); `<https://a.com/a b>` yields two external edges,
  `…/a%20b` and `…/a` (`uri::space-percent-encoded`). Bare URLs keep a
  trailing `.` or `,` (`links::bare-url-stops-at-space-paren-gt-bracket`).
- **Pinned — the two inline-field grammars disagree.** The relation scanner
  (§3.1 step 1) accepts a key after any whitespace, so `Prose then parent::
  [[note]]` is an edge but no `md:inline_field` node or property (the line
  form needs a line start — `links::inline-relation-mid-line`); the
  bracketed `[parent:: [[note]]]` is a plain wikilink edge whose node value
  is `[[note` (`links::inline-relation-bracketed-is-a-plain-wikilink`).
- **Pinned — the anchor scanner runs inside wikilinks**: `[[note^ref]]` also
  projects an `md:anchor` `ref`.
- **Fixed — node spans were UTF-16 code units.** `span_start`/`span_end`
  were JavaScript string indices, so a database written by the reference and
  read by a byte-native engine disagreed on any block with non-ASCII text
  before the feature. §2.3 picks bytes, like `spec/format`; the reference
  converts on write and the node editors convert back on read.
- **Fixed (1.1) — features inside containers counted once per nesting
  level.** A link in a list item yielded an `md:link` node and a
  `references` edge for the list **and** for the item, and the `doc_edges`
  count was 2. Scanners now run over the block's own text (§1), so a node or
  edge belongs to the innermost block only and the count is 1; `md:inline_field`
  nodes follow `spec/properties` 1.1's line form (a list marker and a task
  checkbox may precede the key). Same change as `spec/properties` 1.1.
- **Pinned — `^ref` targets resolve to a document.** `dst_kind` is forced to
  `document` and the anchor kept; block-ref resolution needs the anchor
  index, deferred.
- **Pinned — wikilink aliases are part of the destination.** `[[note|Alias]]`
  has `target = "note|Alias"` and resolves to `phantom:note|Alias`.
- **Pinned — frontmatter predicates keep their case, inline predicates are
  lower-cased**; frontmatter values are only relations when they are exactly
  a wikilink or start with `/` (a `./x.md` value is not a relation); nested
  frontmatter mappings are not walked.
- **Pinned — deletion leaves the graph rows.** A tombstoned document keeps
  its `nodes`, its open outgoing `edges` and its `doc_edges`, and the edges
  pointing at it keep its `doc_id` rather than reverting to a phantom, so
  `links_stale` does not report them. Recorded for a decision.
- **Pinned — `md:inline_field` nodes still exist** alongside the
  `properties` rows the same occurrences produce (`docs/properties-table.md`
  §6 said inline fields "move fully out of `nodes`"; they did not).
- **Pinned — the bare-URL lookbehind.** `(?<![("[])\bhttps?://…` excludes a
  URL directly after `(`, `"` or `[` so the link scanners own those; a port
  without lookbehind checks the preceding character.
- **Pinned — `doc_edges.samples` order** is edge `rowid` order (SQLite's
  `json_group_array` scan order), at most three, nulls (frontmatter edges)
  skipped.

## Decisions

- 2026-10-25, graph 3.0 (store 17.0 slice 3e-i — `docs/modular-core/` M6,
  D8, D9; the contracts `phase-1-contracts.md` §5.1, §5.2): **`edges` is the
  open set; the intervals are the recorder's.** §3.3 is the contracts' text;
  §3.5 and §3.6 are unchanged in effect (an adopted edge keeps its id, a
  tombstoned document's edges stay); §6 `has_anchor` needs no filter; §7
  projects `edges` without the two columns, ordered by the opening commit
  the runner remembers; `intervals.json` → `spec/store/cases/history/
  edge-transitions.json`, `open-edges.json` new. A row's meaning changes
  (two columns the fixtures projected are gone): a major. The Rust
  `omgbase-graph` follows in its own round with the rest of the 17.0 twin.
- 2026-10-20, graph 2.0 (`spec/surface` 5.0 "underscore = engine"): the
  reads §6 pins are rendered under the `links` kind's engine names —
  `_doc_id`, `_block_id`, `_field`, `_dst_id`, `_dst_path`, `_predicate`,
  `_provenance`, `_dst_kind`, `_anchor`, `_path`; the relations
  `_out_links`/`_in_links` — because the surface's row rule became one rule
